# 安全边界

本文说明 Janus 已经做到的隔离、凭据怎样保存，以及使用时必须注意的限制。Janus 是单机、单用户的实验性工具，这些边界不等于安全沙箱。

<a id="agent_isolation"></a>
## Agent 运行环境隔离

每个 Agent 子进程的环境由 Janus 完整构造（`spec_for`、`sandbox_env`），不继承 Janus 自身进程的环境：

- 只从宿主继承 `PATH`、语言环境、`TERM`、`USER`、`LOGNAME`、`SHELL`、`TZ`。
- `HOME`、XDG 目录和 `TMPDIR` 指向 `~/.janus/agents/<id>/` 下的专属目录，Agent 查找 `~/...` 时落在自己的目录里。
- Agent 的配置目录（`CODEX_HOME`、`CLAUDE_CONFIG_DIR`）是 `~/.janus/agents/<id>/home`。用户自己的 `~/.codex`、`~/.claude` 不会被读取或修改。
- 用户在 Agent 设置中填写的环境变量不能覆盖上面这些由 Janus 控制的变量。
- 自定义命令的 Agent 使用同样的隔离环境。

完整的变量清单见[配置](../interfaces/20261031-configuration.md#agent_env)。

例外：Claude Code 做负责人时，Janus 在它的隔离配置 `~/.janus/agents/<id>/home/.claude.json` 中把工作目录标记为已信任。这只修改 Janus 为该 Agent 创建的配置，不修改用户自己的 Claude 配置。

<a id="local_config_import"></a>
## 复制本机配置

选择「复制本机配置」时，只复制与模型接入有关的内容：

| 运行时 | 保留的配置项 |
| --- | --- |
| Codex | `model`、`model_provider`、`model_providers`、`model_reasoning_*`、`model_verbosity`、`model_context_window`、`model_auto_compact_token_limit`、`model_catalog_json`（引用的模型目录一并复制）、`openai_base_url`、`service_tier` |
| Claude Code | `model`，以及 `settings.json` 中配置模型接入点的 `env` 项 |

指令文件、hooks、插件、MCP、Skill、权限和沙箱策略都不复制。

凭据来源：

- 运行时自己的凭据文件（例如 `auth.json`）。
- Claude Code 在 macOS 钥匙串中的登录信息，通过 `security` 命令读取。
- 用户登录 shell 中导出的凭据变量：标准变量，以及配置文件中引用的变量（Codex 的 `env_key`）。Janus 以交互式登录 shell 读取环境，与新开终端看到的一致。

应用中的预览（`/api/local-config`）只列出会复制的文件和变量名，不显示值。

<a id="secrets"></a>
## 凭据保存

| 内容 | 位置 | 权限 |
| --- | --- | --- |
| Agent 的凭据字段、复制来的凭据变量 | `~/.janus/agents/<id>/secrets.json` | `0600` |
| 资源库 MCP 服务器的环境变量和 HTTP header 值 | `~/.janus/secrets/library/<资源 id>.json`（目录 `0700`） | `0600` |
| Janus home | `~/.janus/` | `0700` |

- SQLite、Run 快照、事件和设置接口只记录凭据字段和变量的名字（`secretsSet`、`importedEnv`、`envKeys`、`headerKeys`，以及资源库的 `vars[].set`），不返回值。MCP 的值只在打开会话时读取，放进 `mcpServers` 交给 Agent。
- 登录日志返回给应用前，凭据值替换为 `<secret>`。
- 切换认证方式时，新方式用不到的凭据被删除。

不要把凭据写进 Agent 设置的「环境变量」文本：这些变量作为普通配置保存在 SQLite 中，并通过设置接口原样返回。

<a id="setup_ids"></a>
## 设置对象的 id

Agent、角色、工作区和资源库中的 id 会成为 Janus home 中目录和文件的名字（`agents/<id>/`、`secrets/library/<id>.json`、`library/sources/<id>/`），由 `check_id` 校验：只能用小写字母、数字和 `-`，以字母或数字开头，最长 40 个字符。保存时校验客户端给出的 id，删除 Agent、角色和拼出资源库的路径前也会校验，所以接口请求不能让 Janus 在这些目录之外写入或删除文件。

<a id="workspace_access"></a>
## 工作目录访问

- 任务直接在用户选择的目录中运行，改动立即生效。并行的任务可能修改同一批文件。
- 一个 Agent 能做什么由它自己的权限模式执行。Janus 不做操作系统级的文件、网络或终端限制，权限模式也不是 Janus 的强制安全策略。
- Janus 不提交、不推送。负责人和任务提示中都要求 Agent 不要 commit、push 或部署，但这只是指令，不是强制。
- 非 Git 目录没有 diff，也无法用 Git 回退。

<a id="network_exposure"></a>
## 网络暴露

- HTTP 服务没有鉴权。默认只监听 `127.0.0.1:7878`。
- 把 `JANUS_ADDR` 改为非回环地址，会把设置、凭据名、运行记录、目录检查（`/api/inspect`）和全部控制接口暴露给能访问该地址的任何客户端。
- 看板 MCP 端点的 URL 带令牌，防止其他 Run 和本机其他进程误用；它不是面向网络的认证机制。
- `/api/file` 只返回 `~/.janus/artifacts/` 内的文件，Janus home 中的数据库和凭据不能通过它读取。选择目录用系统的文件夹选择框，服务不提供目录浏览接口。
- 看板 MCP 的 URL 中的令牌由 Run 的随机密钥和 `who` 派生，每个会话只能以自己的身份访问看板，见[看板 MCP 工具](../interfaces/20261031-board_mcp.md#transport)。

<a id="adapter_install"></a>
## 适配器安装

- 适配器来自 npm（`@agentclientprotocol/codex-acp`、`@agentclientprotocol/claude-agent-acp`）。Janus 不校验包的签名，信任边界与手动执行 `npm install` 相同。
- npm 安装带 `--ignore-scripts`，不执行包自带的安装和生命周期脚本。
- 安装命令在 Janus 进程自己的环境中运行（`PATH`、npm 配置、代理），不是 Agent 的隔离环境。
- 来源写在代码中，应用和接口不能指定其他来源。

<a id="library"></a>
## 资源库

规则见[资源库](../domains/20261116-resource_library.md)。

- **不碰 Agent 自己的配置**：资源只在会话启动时通过 `session/new` / `session/load` 的 `mcpServers`、`_meta` 和进程环境变量交给 Agent，不写用户的 `~/.claude`、`~/.codex`，也不写 Janus 隔离目录中的 Agent 配置。Agent 不读取用户自己的 Agent Skill 目录：Skill 只能在应用中新建、从用户选择的目录复制，或从 Git 来源导入。
- **复制本机目录**：只复制普通文件；符号链接只在指向所选目录内部时读取，不跟随到目录之外；跳过隐藏文件（例如 `.env`、`.git`）和 `node_modules`；单个 Skill 最多 2000 个文件、20MB。
- **Git 来源是第三方内容**：只支持 GitHub 链接。Janus 只克隆和读取其中的 `SKILL.md`、`mcp.json` / `.mcp.json`，不执行仓库中的任何文件；扫描不跟随符号链接，克隆时不下载 Git LFS 内容、不弹出凭据输入。Skill 的内容会作为说明交给 Agent，服务器的 `command`、`args`、`url` 原样交给 Agent 启动或连接；是否可信，由用户在导入和给角色选择时判断。
- **资源包是副本**：Run 创建时 Skill 复制到成员自己的资源包。Codex 的 `additionalRoots` 会把资源包加入会话的文件访问范围，Agent 改动资源包只影响这个成员，不影响资源库和其他成员。
- **凭据**：粘贴的配置和 manifest 中写的值保存到 `secrets/library/`（`0600`）；来源更新不覆盖已保存的值。删除资源时一并删除它的值。

<a id="app_updates"></a>
## 应用更新的来源

- 更新只来自 Info.plist 中 `JanusUpdateRepo` 指定的 GitHub 仓库的最新 Release，通过 HTTPS 下载，每个部分都核对 `update.json` 中的 SHA-256。
- 当前应用用固定证书签名时，新版本必须满足当前应用的指定要求（同一个 bundle id、同一张证书），否则拒绝安装。这挡住了被篡改的 Release 附件；能签出被接受的更新的只有持有签名证书的人，证书的 `.p12` 和 Actions secrets 要妥善保管。
- 当前应用是 ad-hoc 签名时没有签名者可以要求，只依靠 HTTPS 和 SHA-256，信任程度与手动下载 DMG 相同。
- 替换脚本只移动应用包、打开新应用，不使用管理员权限；应用所在目录不可写时放弃更新。

<a id="model_prices"></a>
## 模型价格的来源

- 价格只来自 `https://models.dev/api.json`，来源写在代码中（`backend/src/prices.rs`），接口不能指定其他地址。
- 下载用系统的 `curl`，只允许 HTTPS，限时 120 秒、限 64 MB，在 Janus 进程自己的环境中运行（`PATH`、代理）。内容只当 JSON 数据解析，不执行任何部分；每个价格必须是非负的有限数。
- 解析后的表写到 `~/.janus/prices/models.json`，整体替换；下载或解析失败时保留原来的表。
- 价格只用于账单上的估算，标明不是账单；不写进事件，不影响预算、调度、交付或 Agent 的会话。被篡改的价格最多让估算不对。决策见 [ADR：按 models.dev 的价格估算用量](../decisions/20261115-model_prices.md)。

<a id="scope_limits"></a>
## 适用范围

当前是单机、单用户模式，适合本地开发和实验。不提供多租户、远程执行、强隔离执行或生产级访问控制。在用于重要项目之前，先评估共享工作目录、无鉴权和缺少操作系统级沙箱这三项限制。
