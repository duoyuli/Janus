# 安全边界

本文说明 Janus 已经做到的隔离、凭据怎样保存，以及使用时必须注意的限制。Janus 是单机、单用户的实验性工具，这些边界不等于安全沙箱。

<a id="agent_isolation"></a>
## Agent 运行环境隔离

每个 Agent 子进程的环境由 Janus 完整构造（`spec_for`、`sandbox_env`），不继承 Janus 自身进程的环境：

- 只从宿主继承 `PATH`、语言环境、`TERM`、`USER`、`LOGNAME`、`SHELL`、`TZ`。
- `HOME`、XDG 目录和 `TMPDIR` 指向 `~/.janus/agents/<id>/` 下的专属目录，Agent 查找 `~/...` 时落在自己的目录里。
- Agent 的配置目录（`CODEX_HOME`、`CLAUDE_CONFIG_DIR`）是 `~/.janus/agents/<id>/home`。用户自己的 `~/.codex`、`~/.claude` 不会被读取或修改。
- 用户在 Agent 设置中填写的环境变量不能覆盖上面这些由 Janus 控制的变量。
- 自定义命令的 Agent 使用同样的隔离环境。
- [MCP 路由](../domains/20261116-resource_library.md#mcp_router)启动的服务器也一样（`sandbox_at`）：每个资源一个隔离目录 `~/.janus/library/servers/<资源 id>/`，只多出资源自己保存的值，这些值同样不能覆盖 Janus 控制的变量。

完整的变量清单见[配置](../interfaces/20261031-configuration.md#agent_env)。

例外：Claude Code 做负责人时，Janus 在它的隔离配置 `~/.janus/agents/<id>/home/.claude.json` 中把工作目录标记为已信任。这只修改 Janus 为该 Agent 创建的配置，不修改用户自己的 Claude 配置。

<a id="local_config_import"></a>
## 复制本机配置

选择「复制本机配置」时，只复制与模型接入有关的内容：

| 运行时 | 保留的配置项 |
| --- | --- |
| Codex | `model`、`model_provider`、`model_providers`、`model_reasoning_*`、`model_verbosity`、`model_context_window`、`model_auto_compact_token_limit`、`model_catalog_json`（引用的模型目录一并复制）、`openai_base_url`、`service_tier` |
| Claude Code | `model`，以及 `settings.json` 中配置模型接入点的 `env` 项 |

指令文件、hooks、插件、MCP、Skill、权限和沙箱策略都不复制。

凭据来源：

- 运行时自己的凭据文件（例如 `auth.json`）。
- Claude Code 在 macOS 钥匙串中的登录信息，通过 `security` 命令读取。
- 用户登录 shell 中导出的凭据变量：标准变量，以及配置文件中引用的变量（Codex 的 `env_key`）。Janus 以交互式登录 shell 读取环境，与新开终端看到的一致。

应用中的预览（`/api/local-config`）只列出会复制的文件和变量名，不显示值。

<a id="secrets"></a>
## 凭据保存

| 内容 | 位置 | 权限 |
| --- | --- | --- |
| Agent 的凭据字段、复制来的凭据变量 | `~/.janus/agents/<id>/secrets.json` | `0600` |
| 资源库 MCP 服务器的环境变量和 HTTP header 值 | `~/.janus/secrets/library/<资源 id>.json`（目录 `0700`） | `0600` |
| Janus home | `~/.janus/` | `0700` |

- SQLite、Run 快照、事件和设置接口只记录凭据字段和变量的名字（`secretsSet`、`importedEnv`、`envKeys`、`headerKeys`，以及资源库的 `vars[].set`），不返回值。MCP 的值只在打开会话时读取，放进 `mcpServers` 交给 Agent。
- 登录日志返回给应用前，凭据值替换为 `<secret>`。
- 切换认证方式时，新方式用不到的凭据被删除。

不要把凭据写进 Agent 设置的「环境变量」文本：这些变量作为普通配置保存在 SQLite 中，并通过设置接口原样返回。

<a id="setup_ids"></a>
## 设置对象的 id

Agent、角色、工作区和资源库中的 id 会成为 Janus home 中目录和文件的名字（`agents/<id>/`、`secrets/library/<id>.json`、`library/sources/<id>/`），由 `check_id` 校验：只能用小写字母、数字和 `-`，以字母或数字开头，最长 40 个字符。保存时校验客户端给出的 id，删除 Agent、角色和拼出资源库的路径前也会校验，所以接口请求不能让 Janus 在这些目录之外写入或删除文件。

<a id="workspace_access"></a>
## 工作目录访问

- Git 仓库（有提交）上的每个任务在自己的 worktree（`<Janus home>/worktrees/<run>`）中运行，不直接改用户的目录；同一个任务内的子任务共用这个 worktree，并行的子任务可能修改同一批文件。非 Git 目录中任务直接在用户选择的目录中运行，改动立即生效，同一目录上的多个任务也可能修改同一批文件（创建时只提醒）。
- Janus 自己会写用户仓库的 Git 数据，只限于：创建和锁定 worktree（`.git/worktrees/`），验收时在 worktree 里提交（`--no-verify`，不运行仓库的钩子）并创建或快进 `janus/<run>` 分支，移除 worktree。不推送，不改用户检出的分支和目录里的文件，不删除分支；没有配置提交身份时验收报错，不替用户编造身份。见 [ADR：worktree 写入用户仓库的边界](../decisions/20261119-worktree_trust_boundary.md)。
- 创建 worktree 时，原仓库 `.worktreeinclude` 列出的被忽略文件（例如 `.env`）会复制进 worktree，供任务的 Agent 读取。这些文件由用户自己列出；Janus 不复制其他被忽略的文件，也不跟随符号链接。
- 一个 Agent 能做什么由它自己的权限模式执行。Janus 不做操作系统级的文件、网络或终端限制，权限模式也不是 Janus 的强制安全策略。
- 数字员工没有选择权限模式时，Codex 以 Full access、Claude Code 以 Bypass permissions 运行：不经确认就能修改任意文件、执行命令和访问网络。需要审批的场景，在数字员工的「权限」中改选其他模式。见 [ADR：Codex 和 Claude Code 默认不受限运行](../decisions/20261118-unrestricted_default_mode.md)。
- 负责人和任务提示中都要求 Agent 不要 commit、push 或部署，但这只是指令，不是强制。Janus 只在用户验收时提交一次（见上），从不推送。
- 非 Git 目录没有 diff，也无法用 Git 回退。删除一个 worktree 中的 Run 时，没提交的改动存成补丁留在 `<Janus home>/worktrees/deleted/`。

<a id="network_exposure"></a>
## 网络暴露

- HTTP 服务没有鉴权。默认只监听 `127.0.0.1:7878`。
- 把 `JANUS_ADDR` 改为非回环地址，会把设置、凭据名、运行记录、目录检查（`/api/inspect`）和全部控制接口暴露给能访问该地址的任何客户端。
- 看板 MCP 端点的 URL 带令牌，防止其他 Run 和本机其他进程误用；它不是面向网络的认证机制。
- `/api/file` 只返回 `~/.janus/artifacts/` 内的文件，Janus home 中的数据库和凭据不能通过它读取。选择目录用系统的文件夹选择框，服务不提供目录浏览接口。
- 看板 MCP 的 URL 中的令牌由 Run 的随机密钥和 `who` 派生，每个会话只能以自己的身份访问看板，见[看板 MCP 工具](../interfaces/20261031-board_mcp.md#transport)。

<a id="adapter_install"></a>
## 适配器安装

- 适配器来自 npm（`@agentclientprotocol/codex-acp`、`@agentclientprotocol/claude-agent-acp`）。Janus 不校验包的签名，信任边界与手动执行 `npm install` 相同。
- npm 安装带 `--ignore-scripts`，不执行包自带的安装和生命周期脚本。
- 安装命令在 Janus 进程自己的环境中运行（`PATH`、npm 配置、代理），不是 Agent 的隔离环境。
- 来源写在代码中，应用和接口不能指定其他来源。

<a id="library"></a>
## 资源库

规则见[资源库](../domains/20261116-resource_library.md)。

- **不碰 Agent 自己的配置**：资源只在会话启动时通过 `session/new` / `session/load` 的 `mcpServers`、`_meta` 和进程环境变量交给 Agent，不写用户的 `~/.claude`、`~/.codex`，也不写 Janus 隔离目录中的 Agent 配置。Agent 不读取用户自己的 Agent Skill 目录：Skill 只能在应用中新建、从用户选择的目录复制，或从 Git 来源导入。
- 扫描本机目录时，只在所选目录内发现 Skill，跳过符号链接、`.git` 和 `node_modules`。复制时再次核对候选路径，只复制每个 Skill 自己目录内的普通文件，跳过隐藏文件（例如 `.env`、`.git`）和 `node_modules`。符号链接的目标必须位于该 Skill 目录内。单个 Skill 最多包含 2000 个文件，总大小不超过 20 MB。
- **Git 来源是第三方内容**：只支持 GitHub 链接。Janus 只克隆和读取其中的 `SKILL.md`，不执行仓库中的任何文件，也不从仓库导入 MCP 服务器；扫描不跟随符号链接，克隆时不下载 Git LFS 内容、不弹出凭据输入。Skill 的内容会作为说明交给 Agent；是否可信，由用户在导入时判断。
- **资源包是副本**：Run 创建时 Skill 复制到成员自己的资源包。Codex 的 `additionalRoots` 会把资源包加入会话的文件访问范围，Agent 改动资源包只影响这个成员，不影响资源库和其他成员。
- **凭据**：填写或粘贴的配置中的值保存到 `secrets/library/`（`0600`）。删除资源时一并删除它的值。
- **默认给所有数字员工**：`everyone` 的资源对每个 Run 的负责人和所有协作者开放，不再按角色划分。Skill 默认给所有人；MCP 服务器默认收口（`picked`），由用户逐个放开。放开一个带凭据、有副作用的服务器（写数据库、发消息、花钱），就意味着所有数字员工都能调用它。负责人派出子任务后只用来查看，这只是说明，没有检测。见 [ADR：资源库默认给所有数字员工](../decisions/20261119-library_routing.md)。
- **MCP 路由由 Janus 运行服务器**：`everyone` 的 stdio 服务器不再由 Agent 进程启动，而是由 Janus 进程在第一次调用时启动。它不继承 Janus 进程的环境：和 Agent 一样只拿到隔离环境（[Agent 运行环境隔离](#agent_isolation)，`HOME`、XDG 目录和 `TMPDIR` 在 `~/.janus/library/servers/<资源 id>/` 下，跨 Run 保留，删除资源时一起删除）加上资源保存的值，工作目录是 Run 的工作目录。它看不到用户 shell 里的密钥和主目录下的文件（例如 `~/.ssh`），能读写的是 Run 的工作目录和自己的隔离目录。默认同一个 Run 的会话共用一个进程（标成「每个会话单独运行」的除外），在自己的进程组里，Run 停止时连同它派生的进程一起结束。经它写的文件不在 Agent 上报的编辑里，Janus 的文件归属和越界提醒看不到。路由端点只在本机监听地址上，令牌和 `who` 与看板相同；每次调用记一条 `mcp.routed` 事件，不记参数。
- **Skill 路由**：Agent 按 `janus-skills` 列出的路径读取 Janus 目录下资源包里的文件。

<a id="app_updates"></a>
## 应用更新的来源

- 更新只来自 Info.plist 中 `JanusUpdateRepo` 指定的 GitHub 仓库的最新 Release，通过 HTTPS 下载，每个部分都核对 `update.json` 中的 SHA-256。
- 当前应用用固定证书签名时，新版本必须满足当前应用的指定要求（同一个 bundle id、同一张证书），否则拒绝安装。这挡住了被篡改的 Release 附件；能签出被接受的更新的只有持有签名证书的人，证书的 `.p12` 和 Actions secrets 要妥善保管。
- 当前应用是 ad-hoc 签名时没有签名者可以要求，只依靠 HTTPS 和 SHA-256，信任程度与手动下载 DMG 相同。2026.11.18.5 起发布用固定证书签名（私钥只在生成它的机器的 `~/.janus/signing/` 和仓库的 Actions secrets 中），从 ad-hoc 版本更新到它时仍按 ad-hoc 规则接受，之后只接受同一张证书签名的版本。
- 替换脚本只移动应用包、打开新应用，不使用管理员权限；应用所在目录不可写时放弃更新。

<a id="data_upgrade"></a>
## 数据升级与备份

- 升级前的备份 `backups/janus-v*.db` 是 `janus.db` 的完整副本，内容与数据库相同：设置对象、Run 记录和事件，不含凭据（凭据不在数据库里）。目录在 Janus home（`0700`）之下，其他用户进不去；备份文件的权限与 `janus.db` 相同。只保留最近 5 份。
- 迁移只修改 `janus.db`，不读写用户的 Agent 配置和工作目录，不访问网络。
- 数据升级的端到端测试（`just e2e-upgrade`）从本仓库的 Git 标签用 `git archive` 取出旧版本源码并在临时目录构建，不下载发布产物；服务监听 `127.0.0.1` 上一个空闲端口，使用临时 Janus home，不碰用户的 `~/.janus` 和 7878 端口。
- 产品端到端测试（`just e2e-product`）同样只用临时 Janus home 和 `127.0.0.1` 上的空闲端口（应用自启服务的场景另选一个），替身适配器运行仓库中的 `fake_acp.py`，不联网；应用的本地设置写进独立的 `JANUS_DEFAULTS_SUITE`，结束时删除。`--real` 的冒烟测试用独立的临时 home 和另一个空闲端口，只读地拷贝用户 Janus home（默认 `~/.janus`）中的 Codex 和 Claude Code Agent：设置经接口写入，`agents/<id>/secrets.json` 按文件复制，「复制本机配置」再从同样的来源目录复制；从 npm 安装官方适配器（与配置检查相同的来源），结束时删除临时 home 中复制来的凭据，`--keep` 也不保留。

<a id="macos_permissions"></a>
## macOS 权限引导

- 「设置 → 通用 → macOS 权限」引导用户授予完整磁盘访问、应用程序管理和屏幕录制。仅检查当前 Janus 应用的权限；独立服务、其他终端或不同负责进程启动的 Agent 可能需要分别授权。系统权限与 Agent 原生权限模式分别生效，完整磁盘访问不绕过文件所有者权限、SIP 或 Agent 沙箱。
- 三项权限都由应用检测，状态只来自 macOS 对当前进程的回答，用户的操作不会被记成授权。屏幕录制用公开的预检查和申请接口，不在检查中截图。完整磁盘访问通过打开系统 TCC 数据库检测，打开后立即关闭，不读内容。应用程序管理用 TCC.framework 的私有函数 `TCCAccessPreflight` 只查询当前应用自己的状态；它不弹提示、不改任何授权，系统没有这个函数或答案无法识别时显示「无法检测」。
- 用户点击「一键开始授权」后逐项申请或打开系统设置，允许跳过。首次运行和安装标识变化后有未授权的项目时自动显示引导，不自动授予权限、不重置现有授权、不读取 TCC 数据库的内容或其他私人文件，也不改写其他应用来触发权限提示。
- 「重新打开 Janus」只是退出后用 `open` 重新打开当前应用包，不重置、不修改任何授权；删除系统设置中的旧授权记录由用户自己完成。
- `permissions/review.json` 位于 Janus home，只保存安装标识和是否处理过引导，不保存权限状态；记录不授予权限，也不向服务或 Agent 注入权限设置。源码运行不会对宿主终端发起权限申请。
- 决策、限制与依据见 [macOS 权限引导 ADR](../decisions/20261117-macos_permission_guidance.md)。

<a id="model_prices"></a>
## 模型价格的来源

- 价格只来自 `https://models.dev/api.json`，来源写在代码中（`backend/src/prices.rs`），接口不能指定其他地址。
- 下载用系统的 `curl`，只允许 HTTPS，限时 120 秒、限 64 MB，在 Janus 进程自己的环境中运行（`PATH`、代理）。内容只当 JSON 数据解析，不执行任何部分；每个价格必须是非负的有限数。
- 解析后的表写到 `~/.janus/prices/models.json`，整体替换；下载或解析失败时保留原来的表。
- 价格只用于账单上的估算，标明不是账单；不写进事件，不影响预算、调度、交付或 Agent 的会话。被篡改的价格最多让估算不对。决策见 [ADR：按 models.dev 的价格估算用量](../decisions/20261115-model_prices.md)。

<a id="scope_limits"></a>
## 适用范围

当前是单机、单用户模式，适合本地开发和实验。不提供多租户、远程执行、强隔离执行或生产级访问控制。在用于重要项目之前，先评估共享工作目录、无鉴权和缺少操作系统级沙箱这三项限制。
