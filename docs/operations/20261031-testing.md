# 测试

本文说明 Janus 的测试结构、测试用的脚本化 Agent 和编写新测试时的约定。运行环境见[运行手册](20261031-runbook.md)。

<a id="running_tests"></a>
## 运行

```sh
just test
```

等于 `cd backend && cargo test`。提交前再运行 `just lint`，执行与 CI 相同的 `cargo fmt --check` 和 Clippy 检查。

macOS 应用的测试见 [macOS 应用](#macos_app)。

测试不访问网络，不调用真实 Agent，也不安装适配器（脚本化 Agent 是自定义命令类型）。需要本机有 `git` 和 `python3`。

<a id="fake_agent"></a>
## 脚本化 Agent

`backend/testdata/fake_acp.py` 是一个按脚本行事的 ACP Agent，作为 `custom` 类型的 Agent 启动，声明支持 HTTP MCP。`FAKE_DIR` 环境变量指向它的工作目录：

| 文件 | 作用 |
| --- | --- |
| `script.json` | 任务 id → 每次提示的结果列表，最后一个结果重复使用 |
| `calls.log` | Agent 记录收到的会话设置（`session/new` 的 `_meta` 和 `mcpServers`、`set_config_option`）和负责人收到的提示 |
| `lead-go` | 目标模式负责人在这个文件出现前一直工作，然后以文件内容作为最后回复结束 |
| `steer` | 存在时声明 `_session/steering`：一轮进行中收到的 steer 记入 `calls.log`（`steer <内容>`），回复 `injected` |

`script.json` 中可用的结果：`ok`、`fail`、`cancelled`、`slow`、`busy-tool`（进行中的工具调用持续 2.5 秒）、`cancel-usage`（收到 `session/cancel` 后在返回值中附带 `usage`）、`high-ctx`（上报 80% 上下文占用）、`handoff`（写文件并返回 `handoff`、`risks` 和 `reasoning` 方法）、`reject` / `approve`（返回带证据的 `verdict: "rejected"` / `"approved"`）、`write:<文件>`、`edit:<文件>`（写文件并上报一次带 `locations` 的 `edit` 工具调用，再忙 2 秒，让并行的任务重叠）、`permission`（发出带三个选项的 `session/request_permission`）、`elicit`（发出带表单的 `elicitation/create`）、`loop`（给出结果前连续 5 次发出相同的工具调用）、`loop2`（连续 4 轮交替发出 `Edit a.rs` 和 `cargo test`）、`ask`（以提问结束本轮，回答作为下一条提示）、`methods`（每条验收依次带 `test`、`command`、`inspection`、`reasoning`、`unverified` 五种证据方法，另有三条任务级证据）、`badmethod`（第一条验收写不合法的 `method: "vibes"`，核对必须拒绝）、`rich`（发出思考、计划、斜杠命令、一个先进行中再完成并带 diff 的工具调用、上下文用量，并自己切换模式；`session/prompt` 的返回带 token 用量）。默认声明 `loadSession: true`（`no-load` 文件关闭、`fail-load` 文件模拟加载报错），收到 `session/load` 时记入 `load <sid>`。用量场景（供只读的用量账本使用）：`usage`（上报三次上下文快照和一个 `cost`，`session/prompt` 的返回带主循环 1200 input / 300 output / 1500 total，以及 `_meta.quota.model_usage` 中主模型 1500 和一个子 Agent 500 两行）、`usage-quiet`（只报上下文快照，完全不上报 token）、`usage-turns`（第一轮 1000 token 后提问，回答后的一轮报 2500，两轮相加是 3500）。`session/set_mode` 记入 `calls.log`（`mode <id>`），每轮提示里的文件引用也记入（`links <路径>…`）。FAKE_DIR 中有 `goal-sticky` 文件时，负责人把 `/goal` 报告为进行中且从不清除，像检查不运行的 Claude Code；Janus 问它目标是否完成时回复 `GOAL_DONE` 加 `lead-go` 的内容，收到 `_session/goal` 时记入 `goal clear` 并报告目标已清除。

作为目标模式负责人时，它先确认说明（`calls.log` 记 `brief ok`），再在收到 `/goal …` 后等待 `lead-go`。计数器保存在 `FAKE_DIR` 中，同一任务的多次尝试（不同进程）共用脚本进度。

<a id="harness"></a>
## 测试夹具

`flow_tests::harness(name, members, script)`：

- 在系统临时目录创建 `janus-flow-<name>-<pid>`，内含一个初始化过的 Git 仓库作为工作区。
- 注册一个 `fake` Agent，声明 `mode`（`read-only` / `ask` / `agent` / `full`）权限控制项。
- `members` 是 `(角色 id, 是否可写)` 列表，第一个是负责人；不可写的角色使用 `read-only` 模式。
- 测试构建下 `Runtime::leads` 允许 `custom` 类型做负责人，以便脚本化 Agent 担任负责人。

辅助函数：`start`（创建 Run 并以负责人身份提交一份编排）、`finish_lead`（让脚本化负责人结束目标）、`act`（发送 Run 操作）、`tool`（以负责人或协作者身份调用看板工具）、`wait_until`（等待事件条件）、`events`、`has`、`status`。

<a id="test_conventions"></a>
## 约定

- 每个 `flow_tests` 测试给 `harness` 传唯一的 `name`。测试并行运行，名字相同的测试会共用并互相删除临时目录，造成随机失败。
- 测试结束时删除临时目录。
- 新增事件类型或改变流程时，在 `flow_tests` 中用脚本化 Agent 覆盖，不依赖真实 Agent。
- 真实 Agent 的验证（例如 Codex 负责人 + Claude Code 协作者）通过应用手动运行，结果不进入自动测试。
- 需要等待 SwiftUI 布局或延后滚动的界面测试使用 `@MainActor async`，等待期间通过 `await Task.sleep` 让出主线程。同步 `@MainActor` 测试内反复调用 `RunLoop.main.run(until:)` 不能可靠执行排入主队列的工作，会在滚动修正执行前断言失败。`ChatScrollTests` 先验证主队列中的回调已执行，再检查打开位置、向上翻阅和跟随新消息；修复夹具时保留这些行为断言，并在 CI 的最低支持版本上验证。
- 注入滚动手势的窗口测试把窗口加入显示列表，以便在其他主线程测试运行时也获得显示周期；窗口透明且忽略真实鼠标事件，合成手势直接发送给滚动视图。结束时关闭窗口，避免真实输入或遗留窗口影响后续测试。

## macOS 应用

- `just test-mac`（`cd frontend && swift test`）运行 `frontend/Tests/JanusTests` 中的 Swift Testing 测试：事件推导、看板事实、用量账本（与后端共用的 `usage_cases.json`、每轮相加、按模型的上报、上下文快照不累计、缺失与 0、费用的累计与重置、负责人单列、尝试的结局、等待时间、回放位置、提醒只读、金额的美元写法，`UsageLedgerTests`；用量卡片和时间段账单在浅色与深色下的绘制，`SessionViewTests`）、JSON、Markdown 文档的解析、Run 中 Markdown 文档的收集、负责人卡住和改了同一个文件的待处理事项、越界和结果对不上的待处理事项与认领（`tracesOpenOnTheBoardUntilTheLeadActs`）、插话被读到后不重复显示、环境变量文本、Plan 控制项过滤、资源库条目的文案（来源、来源中已删除、缺少的值、按运行时的不支持原因，`LibraryTests`）、收件箱（只取运行页标为等人处理的条目、已结束 Run 的验收与继续提醒、稍后处理到时间回来且会卡住 Agent 的事项不能推迟、选择题就地回答的按钮和文案，`InboxTests`）、时间文案、用量数字和缺失状态、首页按原因合并的问题、审计日志按前缀分类和只编译一次的正则（`FormatTests`）、diff 的解析和审阅意见合成的消息、系统通知只发新事项（`DiffTests`）、会话的计划、控制项、命令、用量的读取和输入框补全、用量的「本会话 / 上一轮」标签与 Run 累计分开、内联 diff 的行、Agent 回显的看板工具调用（`mcp.janus.*`、`mcp__janus__*`）不重复显示、会话只在停在底部时跟随新内容（`ChatFollow`，`SessionViewTests`）、在真实窗口中用触控板手势往上翻后新回复不移动视图、回到底部后继续跟随、打开时停在最新处（`ChatScrollTests`），以及应用更新（`UpdaterTests`：版本号比较、只下载变化的部分、`update.json` 的读取、用 `codesign` 现场签一个最小应用包来检查签名校验、版本号不符和文件被改动后拒绝安装）。只装命令行工具时，`@Test` 宏插件在 `usr/lib/swift/host/plugins/testing` 下、不会自动加载，`just test-mac` 检测到这种情况会加上 `-plugin-path`；CI 的 macOS 运行环境自带 Xcode，直接运行 `swift test`。
- `MacPermissionsTests` 使用注入的系统接口，覆盖首次启动、同版重启、版本 / 构建 / 路径 / 代码哈希变化、逐项引导、拒绝和跳过、实时撤权、系统设置打开失败、确认记录保存失败，以及源码运行不申请权限。手动确认不等于系统授权；测试不访问 TCC 数据库、不触发系统授权弹窗。界面验收使用隔离的应用包和 Janus home，通过快照命令检查权限页与首次引导，不与滚动交互测试并行渲染。
- 查看界面：设置 `JANUS_SNAPSHOT_DIR` 后，应用每 0.7 秒读取一次 `<目录>/cmd`，逐行执行 `open inbox`、`open run:<id>`、`open home:<工作区>`、`open settings:<general|agents|roles|library|adapters|usage|permissions|updates>`、`page <board|audit|team|task:<id>|agent:<id>|replay:<seq>>`、`fold <usage|progress|risks|tasks|all|任务> <open|closed>`（展开或收起工作台的用量明细、运行级风险、进展时间线和逐条验收，用来截展开态）、`role <id>`、`workspace <id>`、`close-sheet`（也关闭设置浮层）、`doc <路径>`（打开文档窗口）、`paste <图片路径>`（把图片交给当前窗口第一个输入框的粘贴处理，使用私有剪贴板）、`size <宽>x<高>`、`shot <名字>`、`snooze-first` / `wake-all`（把第一条可推迟的事项放一小时后 / 让所有推迟的事项回来）、`close-window`（关闭主窗口，检查只剩菜单栏图标）、`appearance <light|dark|system>`（只在应用内切换浅色或深色外观，不改系统设置）、`review <任务>`（打开这个任务最新 diff 的审阅窗口）、`window <标题开头>`（之后的 `shot` 截标题以它开头的窗口，不带参数时恢复默认）、`inbox-act <条目>:<按钮>`（按位置点收件箱里的就地回答按钮，走和点击相同的代码）、`density <detail|normal|summary>`（切换会话的显示档位）、`draft <任务或 Agent> <文字>`（往会话的输入框里填文字，用来看斜杠命令和 `@` 文件的候选）、`state <名字>`（把当前页面、收件箱、设置浮层和 Dock 图标的状态写成 `<名字>.json`），截图保存为 `<目录>/<名字>.png`。截的是应用自己的窗口，不需要屏幕录制权限；窗口服务器返回纯色图片时（例如没有屏幕录制权限或窗口不在当前桌面）改用视图自身渲染。配合 `JANUS_HOME` 和 `JANUS_ADDR` 指向一份数据副本使用，不影响正在运行的 Janus。
