## Run、任务与会话编排

### Run 与任务调度

- **O01 · Run 的恢复方式**。`App.runs` 记录当前进程持有的 Run。服务重启会把未结束的 Run 和尝试标为中断。恢复中断或失败的 Run 时，编排器从事件重建任务、重试次数和未送达消息，再启动负责人目标。在历史交付或验收记录上发消息只重新打开负责人对话，验收历史交付也可以直接写入数据库。 [actions.rs:45](https://github.com/duoyuli/Janus/blob/61dc2648c2697da355b79a4b125dce3d6915f59f/backend/src/orchestrator/actions.rs#L45)、[actions.rs:460](https://github.com/duoyuli/Janus/blob/61dc2648c2697da355b79a4b125dce3d6915f59f/backend/src/orchestrator/actions.rs#L460)、[actions.rs:653](https://github.com/duoyuli/Janus/blob/61dc2648c2697da355b79a4b125dce3d6915f59f/backend/src/orchestrator/actions.rs#L653)、[actions.rs:689](https://github.com/duoyuli/Janus/blob/61dc2648c2697da355b79a4b125dce3d6915f59f/backend/src/orchestrator/actions.rs#L689)
- **O02 · 调度循环的启动与交付**。`Driving` 记录驱动任务是否仍在运行。交付后的对话可以追加编排，在原驱动任务退出后启动新的调度循环。当没有执行中或可启动的任务时，调度器根据负责人的目标状态决定继续等候、交付或报告负责人失败。因此，交付可能包含失败或阻塞的子任务，负责人会话也可能在驱动任务退出后继续对话。 [orchestrator.rs:520](https://github.com/duoyuli/Janus/blob/61dc2648c2697da355b79a4b125dce3d6915f59f/backend/src/orchestrator.rs#L520)、[lifecycle.rs:103](https://github.com/duoyuli/Janus/blob/61dc2648c2697da355b79a4b125dce3d6915f59f/backend/src/orchestrator/lifecycle.rs#L103)、[lifecycle.rs:229](https://github.com/duoyuli/Janus/blob/61dc2648c2697da355b79a4b125dce3d6915f59f/backend/src/orchestrator/lifecycle.rs#L229)、[lifecycle.rs:445](https://github.com/duoyuli/Janus/blob/61dc2648c2697da355b79a4b125dce3d6915f59f/backend/src/orchestrator/lifecycle.rs#L445)
