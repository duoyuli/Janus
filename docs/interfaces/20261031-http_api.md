# HTTP API

本文是编排器 HTTP 接口的参考：路由、请求与响应、SSE 事件流和 Run 操作。看板 MCP 端点见[看板 MCP 工具](20261031-board_mcp.md)，事件字段见[事件参考](20261031-events.md)。

所有路由在 `backend/src/http.rs` 的 `router` 中注册，处理函数按服务对象分在 `backend/src/http/` 下。服务没有鉴权，只应监听回环地址，见[安全边界](../operations/20261031-security.md#network_exposure)。

<a id="errors"></a>
## 通用约定

- 请求和响应体都是 JSON（导出和文件读取除外）。
- 处理失败时返回状态码和纯文本错误信息：参数或业务错误 400，资源不存在 404，状态冲突 409，看板令牌错误 403。
- 错误信息是中文，直接用于界面提示。处理函数返回 `ApiError`：`App` 报的错是 400，Run 操作和删除的拒绝（`Refused`）按种类是 404、409 或 400。

<a id="setup"></a>
## 设置对象

`POST /api/setup/{kind}` 的 body 就是设置对象本身，带 `id` 表示更新，不带表示新建；返回保存后的对象。`GET /api/setup` 返回的默认角色在改过的项有新版默认文本时带 `seedUpdates`（`{字段: 新文本}`）。字段和校验规则见 [Agent、角色与工作区](../domains/20261031-agents_and_roles.md)。

- 连接返回时不包含凭据字段的值。
- Agent 类型（`/api/meta` 的 `kinds`）中，`env: true` 的认证方式由环境变量设置（Claude 的自定义 API，`auth: "apikey"`），`template` 是应用「填入模板」带入的模板。保存连接时在 `envText` 中传入多行赋值，读取时 `env` 中的字符串是普通值（空字符串表示取消设置），`null` 表示私有值已保存。编辑时在 `envText` 中单列该变量名可沿用它，省略该行会移除它。
- 配置检查的进度写在连接对象上，应用轮询 `/api/setup` 读取。

<a id="library"></a>
## 资源库

规则见[资源库](../domains/20261116-resource_library.md)。除 `GET /api/library/mcp/{id}/values` 外，所有响应都不含 MCP 的值。

`GET /api/library` 返回 `{ "items": [...], "sources": [...], "skillRouter": { "catalog": "list" | "search" } }`。`skillRouter.catalog` 说明新 Run 的 `janus-skills` 目录直接列出每个 Skill（`list`）还是让 Agent 按关键词搜索 `catalog.txt`（`search`），见 [Skill 路由](../domains/20261116-resource_library.md#skill_router)。资源的字段：

| 字段 | 含义 |
| --- | --- |
| `id`、`kind`、`name`、`description`、`revision`、`updatedAt` | 见[资源](../domains/20261116-resource_library.md#model) |
| `origin` | `{"type": "created"}`、`{"type": "folder", "path"}` 或 `{"type": "git", "source", "path"}` |
| `server` | MCP 才有：`{"transport": "stdio", "command", "args", "envKeys", "process"}`，或 `{"transport": "http" \| "sse", "url", "headerKeys"}` |
| `vars` | MCP 才有：`[{"name", "set"}]`，每个变量是否已有值 |
| `source` | Git 来源导入的才有：`{"url", "inSource"}`，`inSource` 为 `false` 表示来源最近一次拉取时已经没有它 |
| `uses` | Skill 才有：`{"sessions", "lastAt"}`，读过它的会话数和最近一次的时间（没读过时 `lastAt` 为 `null`），见 [Skill 的使用记录](../domains/20261116-resource_library.md#skill_uses) |
| `hints` | Skill 才有：描述的改进提示，`[{"kind": "short" \| "noWhen"}]`、`{"kind": "long", "chars", "kept"}`、`{"kind": "alike", "skill"}`，没有时为空数组，见 [Skill 的改进提示](../domains/20261116-resource_library.md#skill_hints) |

来源的字段：`id`、`url`、`cloneUrl`、`repo`、`gitRef`、`path`、`commit`、`fetchedAt`、`latest`、`checkError`、`checkedAt`、`warnings`、`offers`（`[{"kind", "path", "name", "description"}]`）、`updateAvailable`、`imported`（`[{"path", "item", "name"}]`）。

MCP 服务器带 `warm`（服务启动后准备过才有，对应当前 `revision`）：`{"state": "preparing"}`、`{"state": "ready", "tools": 数量}` 或 `{"state": "failed", "error": 原因}`。新建、修改（`POST /api/library/mcp`、`PUT /api/library/mcp/{id}`）和粘贴导入（`POST /api/library/mcp/import`）后自动在后台准备；`POST /api/library/mcp/{id}/warm` 重新准备，立即返回，见 [MCP 路由](../domains/20261116-resource_library.md#mcp_router)。

资源库里的每项资源都给所有数字员工，没有「给谁用」的接口；角色也没有 `resources` 字段，见 [Run 和会话怎样拿到资源](../domains/20261116-resource_library.md#delivery)。

MCP 服务器的 body：`{"name", "description", "transport": "stdio" | "http" | "sse", "command", "args", "url", "process": "perRun" | "perSession", "vars": [{"name", "value"}]}`。`process` 只对 stdio 有意义：MCP 路由怎样运行它，默认 `perRun`（同一个 Run 共用一个进程），见 [MCP 路由](../domains/20261116-resource_library.md#mcp_router)。stdio 服务器的 `command` 可以是整行命令（不带 `args` 时按 shell 规则拆分）；`vars` 是环境变量（stdio）或 HTTP header（http、sse），`value` 是字符串时写入（空字符串清除这个值），没有 `value` 字段时保留已保存的值，列表中没有的变量连同值一起删除。

<a id="folder_skills"></a>
### 本机目录导入

1. 向 `/api/library/skills/scan` 提交本机目录 `path`。响应包含解析后的绝对目录 `path`、候选列表 `offers`、已导入的条目 `imported` 和 `warnings`。`offers` 和 `imported` 与 Git 来源的列表格式相同，条目的路径相对于所选目录。空字符串 `""` 表示所选目录本身。超过 500 个候选路径或 8 层深度时，`warnings` 提示改选子目录。全部候选都在深度上限以外时，响应仍返回警告和空列表。
2. 向 `/api/library/skills/import` 提交扫描返回的 `path` 和选中的候选路径 `paths`，至少选择一项。提交时会重新核对每个候选路径，路径不在候选列表中时返回 400。响应包含 `imported`（成功复制或已导入的条目）和 `warnings`（每项复制失败的原因）。重复提交同一 Skill 目录时返回已有条目。

省略 `paths` 时，`/api/library/skills/import` 直接从 `path` 复制单个 Skill，并返回该资源对象。

<a id="adapters"></a>
## ACP 适配器

`GET /api/adapters` 返回 `{ "adapters": [...], "dir": "<适配器目录>" }`，每项字段见 [ACP 适配器管理](../architecture/20261031-adapters.md#api_shape)。

`POST /api/adapters/{id}/{action}`，`id` 是 `codex` 或 `claude`：

| `action` | body | 说明 |
| --- | --- | --- |
| `install` | `{"version": "1.1.2"}`，可省略 | 后台安装并设为当前版本；省略版本时安装最新版。当前版本已固定时这是「恢复自动更新」：先解除固定，最新版已经装过就直接切过去，没装过才下载 |
| `use` | `{"version": "<已安装的版本>"}` | 切换当前版本并固定它：之后的自动升级不再动它，服务重启后保持；用 `install` 恢复 |

服务自己定时检查并安装新版本，见[自动检查与升级](../architecture/20261031-adapters.md#update_check)；没有手动检查更新的接口。成功时立即返回最新的适配器列表；安装的结果通过 `GET /api/adapters` 的 `job` 字段读取（自动升级是 `action: "auto"`，手动的是 `"install"`）。同一适配器已有任务在进行时返回 400。

<a id="runs"></a>
## Run

### 创建

```http
POST /api/runs
Content-Type: application/json

{ "goal": "为 calc 增加除法", "workspace": "w123" }
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `goal` | 是 | 目标，不能为空；带 `images` 时可以为空 |
| `workspace` | 是 | 工作区 id |
| `images` | 否 | 随目标粘贴的图片，见[图片](#images) |
| `maxTokens` | 否 | 本次 Run 的 Token 用量参考值（正整数），默认取 `JANUS_RUN_TOKEN_BUDGET`。达到参考值后所有任务照常运行 |

请求体只能有上表的字段，多出的字段（例如已经去掉的 `maxCostUsd`）返回 400，不创建 Run。Run 先进[派发队列](../domains/20261031-run_lifecycle.md#dispatch_queue)：有空位时开始准备好才返回；没有空位时返回 id，Run 的状态是 `queued`，空出位置后自动开始。工作区、团队或 Agent 不能用时直接返回 400，不排队。

返回 `{"id": "<run id>"}`。校验规则见 [Run 生命周期](../domains/20261031-run_lifecycle.md#create_run)。工作区是有提交的 Git 仓库时，Run 在自己的 worktree 中运行，`GET /api/runs/{id}` 的 `run.cwd` 是 worktree 的路径，`run.config.worktree.repo` 是原仓库，见[工作目录](../domains/20261031-run_lifecycle.md#workspace_model)。

<a id="run_list"></a>
### 列表

`GET /api/runs` 从新到旧列出 Run，一次一页，返回 `{"runs": [...], "next": "<cursor>"}`：

| 参数 | 说明 |
| --- | --- |
| `kind` | `goal`（默认）、`chat`（[对话](#chats)）、`loop`（[值班](#loops) 的会话）或 `dream`（[团队记忆的整理](#memories)），分开列出；其他值返回 400 |
| `loop` | 只列这个值班派出的目标 Run |
| `workspace` | 只列这个工作区的 Run（快照中的 `config.workspace.id`） |
| `attention` | `1` 时只列可能需要用户的 Run（`planning`、`running`、`delivered`、`interrupted`、`failed`），不论有多旧；收件箱和退出确认读它 |
| `limit` | 每页几个，默认 50，最多 500 |
| `cursor` | 上一页返回的 `next`，读它后面的一页；格式不对返回 400 |

每行另有 `origin`（`user` 或 `loop`）、`loopId`（派出它的值班，或这个值班会话的值班）、`dispatchKey` 和 `sourceUrl`（值班派发时给的）。排队中的 Run 另有 `queuePosition`（1 是下一个），和状态在同一条查询里算出，按全局队列计，不受 `workspace` 过滤和分页影响；`GET /api/runs/{id}` 的 `run` 也带它，其余 Run 为 `null`。

`next` 为 `null` 时已经是最后一页。排序按创建时间再按 `id`，翻页不会漏掉或重复同一毫秒创建的 Run。应用的侧栏对话和工作区页的任务记录滚动到底时读下一页，所以无论有多少都能看到；收件箱读 `attention=1`，等用户处理的 Run 不会因为有了更新的 Run 而消失；角色统计只看最近的 50 个。

<a id="global_stream"></a>
### 全局事件流

`GET /api/stream` 是应用跟进所有 Run 的唯一通道（SSE），代替轮询。它不带完整事件，只推短通知，应用需要时再按 Run 读：

| SSE 事件 | `data` | 含义 |
| --- | --- | --- |
| `ready` | `{}` | 流已打开：应用此时读一次列表和收件箱 |
| `event` | `{"run", "seq", "type"}` | 某个 Run 有了一条新事件；应用只对收件箱跟进的 Run 读它的新事件（`GET /api/runs/{id}?after=`） |
| `run` | `{"run", "status", "loop"}` | 某个 Run 的状态变了（`set_status`、历史交付的验收）；应用读一次列表。值班派出的 Run 带 `loop`（值班的 id），应用重读那一个值班 |
| `loop` | `{"loop"}` | 某个值班变了（设置、下次醒来的时刻、醒着与否、派出的 Run）；应用只重读这一个值班（`GET /api/loops/{id}`），404 时从列表移除 |
| `memory` | `{"workspace"}` | 某个工作区的[团队记忆](#memories)变了（写、改、删笔记，整理开始或结束）；应用只在读过这个工作区的团队记忆时重读它 |
| `lagged` | `{}` | 应用读得太慢漏了通知：重新读列表和收件箱 |

同一状态再设一次不发通知。一批通知在应用里合并处理（300 毫秒内的合成一次读取）。打开着的 Run 页仍用自己的 `/api/runs/{id}/stream` 读完整事件。

<a id="run_preflight"></a>
### 创建前的提醒

`GET /api/runs/preflight?workspace=<工作区 id>` 返回 `{"warnings": ["…"]}`，是创建这个工作区的 Run 之前要告诉用户的事，只是提醒，不阻止创建（应用弹出「继续执行？」，用户确认后照常 `POST /api/runs`）：

- Git 仓库里有还没提交的改动：列出前 5 个文件，说明这些改动不会带进任务（任务从 `HEAD` 开始，在单独的副本里进行）。
- 非 Git 目录上有进行中（`planning`、`running`）的 Run：每个一条，说明两个任务会直接改同一批文件。

没有要提醒的事时返回空数组。工作区不存在或团队无效时返回 400，和创建时的错误相同。

<a id="images"></a>
### 图片

`POST /api/runs` 和 `message` 操作都可以带 `images`：

```json
{ "images": [{ "data": "<base64，也可以是 data URL>", "name": "截图.png", "mimeType": "image/png" }] }
```

- 类型按文件头识别，支持 PNG、JPEG、GIF、WebP，`mimeType` 只作参考。每张最多 10 MB，一次最多 10 张，否则返回 400，不保存任何图片。
- 带图片时 `goal` 或 `text` 可以为空。
- 请求体上限是 160 MB。
- 保存位置、Agent 收到的形式和事件字段见[图片附件](../domains/20261031-run_lifecycle.md#attachments)。

<a id="run_detail"></a>
### 详情

`GET /api/runs/{id}` 返回：

```json
{
  "run": { "id": "rmwhyr31u", "goal": "...", "cwd": "...", "status": "running", "config": {} },
  "events": [],
  "live": true
}
```

带 `?after=<seq>` 时 `events` 只包含 `seq` 大于该值的事件，应用[收件箱](../architecture/20261031-frontend.md#inbox)用它增量读取正在进行的 Run，所以这个接口只读新事件，不做别的计算。不带时返回全部事件。

`run.kind` 是 `goal`（目标）、`chat`（[对话](#chats)）、`loop`（[值班](#loops) 的会话）或 `dream`（[团队记忆的整理](#memories)，只有一轮，`resumeRun` 和 `message` 返回 400）。`live` 表示 Run 当前在内存中运行。`live` 为 `false` 的 Run 能执行的操作按状态：排队中（`queued`）只有 `start` 和 `cancel`；刚离开队列、还在准备（`planning`）的目标 Run 什么都不接受，返回 409；没能开始的（`failed` 且没有快照）只有 `resumeRun`，它重新排队；其余只有 `accept`、`resumeRun` 和 `message`，值班的会话另有 `answer`（先打开会话，回答它的问题）。

<a id="run_delete"></a>
### 删除

`DELETE /api/runs/{id}` 删除一个 Run 在 Janus 里留下的全部数据。值班的会话 Run 不单独删：这个接口对它删除整个值班，和 `DELETE /api/loops/{id}` 相同。

- SQLite 中这个 Run 的 `runs`、`events`、`attempts`、`artifacts`、`verifications` 和 `commands` 行。
- `$JANUS_HOME` 下这个 Run 的三处目录（`Layout::run`）：`data/runs/<run>/`（成员资源包、图片附件、产物）、`logs/runs/<run>/`、`work/runs/<run>/`；对话是 `data/chats/<run>/`、`logs/chats/<run>/` 和它的工作目录 `work/chats/<run>/`，里面 Agent 留下的文件一起删除。
- 这个 Run 的 worktree（`work/runs/<run>/`）：先把还没提交的改动存成补丁 `data/deleted-runs/<run>.patch`，再从原仓库移除 worktree。已经合并回源分支的结果不受影响。
- 这个 Run 的会话在 Agent 配置目录里留下的会话记录（`forget_sessions`）：会话 id 取自 `attempt.started`、`agent.status` 和 `session.prompt` 事件，删除 Claude Code 的 `projects/<项目>/<会话>.jsonl`（和同名目录）、`session-env/<会话>/`，Codex 的 `sessions/<日期>/rollout-<时间>-<会话>.jsonl`。

删除和恢复同一个 Run 依次进行，不会删到一半时被一条消息恢复。已交付的 Run 还开着负责人会话时，先停止写入它的事件，再关闭会话，会话关闭时说的话不再写进已删除的 Run。先移除 worktree，再删除目录，最后在一个事务里删除 SQLite 行：worktree 里的改动存不成补丁（暂存或读出改动失败、补丁写不进去）或某个目录删不掉时返回 400，worktree 和 Run 的行都还在，排除原因后用同一个请求再删一次即可。

工作区目录里的文件不在删除范围内：非 Git 目录中任务改过的文件保持原样；Git 仓库中任务的改动在 worktree 里，按上面存成补丁。`planning`、`running` 的目标 Run 返回 409：先停止它，因为进行中的会话和尝试还会写事件。对话只有自己的一个会话，会话打开时也可以删除：先停止写入事件，再关闭会话。Run 不存在返回 404，成功返回 `{"ok": true}`。应用在删除前确认，见 [macOS 应用](../architecture/20261031-frontend.md#interaction)。

<a id="chats"></a>
### 对话

```http
POST /api/chats
Content-Type: application/json

{ "role": "marketing" }
```

`role` 是数字员工 id，必须绑定了 Agent。返回 `{"id": "<run id>"}`，这时会话已经开始打开，用户的第一条消息用 `message` 操作发送，它成为对话的标题（`run.goal`，之前为空）。对话是 `kind` 为 `chat` 的 Run：`GET /api/runs/{id}`、事件流、`message` 等操作、用量账本、`files` 和删除都和目标 Run 用同一组接口。规则见[对话](../domains/20261120-chats.md)。数字员工不存在或没有绑定 Agent、Agent 的运行环境不完整时返回 400，不创建任何东西。

<a id="loops"></a>
### 值班（Loop）

工作区的值班见 [工作区值班](../domains/20261121-loops.md)。

```http
POST /api/workspaces/w123/loops
Content-Type: application/json

{ "prompt": "用 gh 看 owner/repo 新开和更新的 issue……", "schedule": { "cron": "0 9 * * 1-5", "tz": "Asia/Shanghai" }, "wakeNow": true }
```

| 字段 | 说明 |
| --- | --- |
| `prompt` | 不能为空，每次醒来原样交给值班。没有名字字段：值班第一次醒来时用 `set_name` 给自己起名，见[值班是什么](../domains/20261121-loops.md#loop_model) |
| `schedule` | `{"cron": "<5 段 cron>", "tz": "<IANA 时区>"}`，`tz` 省略时用服务所在机器的时区；`null` 表示只在叫它时醒。表达式不对、时区不存在或永远不会到点时返回 400，见[时间表](../domains/20261121-loops.md#schedule) |
| `wakeNow` | 只用于新建：为真时立即醒来一次，否则等时间表到点 |

工作区没有负责人、负责人的 Agent 不能运行或工作目录不存在时返回 400。返回值班：存储的字段（`id`、`workspace`、`name`（起名之前为空）、`prompt`、`schedule`、`state`、`run`），加上 `title`（`name`，没有时是提示的第一行）和 `status`：`phase`（`sleeping`、`awake`、`paused`、`failed`）、`nextWakeAt`（毫秒，没有时为 `null`）、`nextWakeReason`（`timer` 是时间表，`self` 是它自己约的）、`nextWakeWhy`（它约的时候说的原因）、`lastWokeAt`、`wakes`（醒来次数）、`lastSummary`（上次醒来最后一条消息的第一行）和 `dispatched`（派出的 Run 按状态计数）。`GET /api/loops` 返回 `{"loops": [...]}`。

`GET /api/loops/schedule?cron=<表达式>&tz=<时区>` 按新建时的规则检查一个时间表，返回 `{"cron", "tz", "next"}`：整理过空白的表达式、用的时区和接下来三次到点的时刻（毫秒）；不对时返回 400 和原因。应用的表单用它显示「接下来」，不自己解析 cron。

`PUT` 带同样的 `prompt`、`schedule`，时间表变了从现在重新排（它约的还没到的时间保留）。`wake` 立即醒来（暂停时也可以），正醒着时等这一轮结束再醒；`pause`、`resume` 返回值班。`DELETE` 删除值班和它的会话 Run，派出的 Run 保留，删到一半失败时可以重试；删除工作区时它的值班一并删除。`status` 另有 `watchesFiles`：工作区在 Git 仓库里、能看出值班改了哪些文件时为真，还没醒过时为 `null`。

值班的会话是 `kind` 为 `loop` 的 Run（`run` 字段是它的 id），`GET /api/runs/{id}`、事件流、`message`、`interrupt`、`answer` 等操作都和对话一样，`pause`、`resume`、`cancel` 返回 400（值班在值班的接口暂停或删除）；`GET /api/runs?kind=loop` 列出值班的会话。值班派出的目标 Run 用 `GET /api/runs?loop=<Loop id>` 列出。

<a id="memories"></a>
### 团队记忆

工作区的团队记忆见[团队记忆](../domains/20261123-team_memory.md)。Agent 只经 `janus` MCP 工具读写笔记，这里是给应用的接口。

- `GET /api/workspaces/{id}/memories` 返回 `{"memories": [...], "consolidation": {...}}`。`memories` 按最近修改排序，每条：`id`、`workspace`、`kind`、`title`、`hook`、`body`、`run`（最后写它的 Run，用户改的为 `null`）、`who`（成员 id 或 `user`）、`author`、`createdAt`、`updatedAt`，以及 `runGoal`、`runStatus`（那个 Run 的目标和状态，Run 已删除时为 `null`）。`consolidation`：`running`（正在进行的整理的 Run id，没有时为 `null`）、`last`（上一次整理的 `run`、`at`、`status`，没有时为 `null`）、`deliveredSince`（上次整理以来交付或验收的目标 Run 数）。工作区不存在时返回 400。
- `PUT /api/memories/{id}` 带 `kind`、`title`、`hook`、`body` 中要改的几项，返回改后的笔记，来源变为用户（`who` 为 `user`，`run` 为 `null`）。空字段、未知类型、超过长度返回 400，笔记不存在返回 404。
- `DELETE /api/memories/{id}` 删除一条笔记；不存在返回 404。
- `POST /api/workspaces/{id}/memories/consolidate` 现在开始整理，返回 `{"run": "<整理的 Run id>"}`。已经在整理时返回 409，没有笔记、负责人不能运行时返回 400。整理是 `kind` 为 `dream` 的 Run，用 `GET /api/runs/{id}` 和事件流读，`GET /api/runs?kind=dream` 列出。

<a id="run_usage"></a>
### 用量账本

`GET /api/runs/{id}/usage?until=<seq>` 按这个 Run 到 `seq` 为止的事件（不带 `until` 时是全部事件）算出只读的用量账本（`backend/src/usage.rs`），Run 不存在时返回 404：

```json
{
  "text": "用量：15,400 tokens（部分上报） · 费用：未上报 · 耗时 3 分 12 秒（总时长）",
  "run": {
    "id": "run",
    "tokens": { "total": 15400, "input": 12000, "output": 3400, "cachedRead": null, "cachedWrite": null, "thought": null },
    "turns": 6,
    "context": { "used": 52000, "peak": 61000, "size": 200000, "reports": 3 },
    "cost": { "lines": [], "reportedSessions": 0, "missingSessions": 4 },
    "durationMs": 192000,
    "waitMs": null,
    "sessions": 4,
    "reportedSessions": 2,
    "missingSessions": 2,
    "completeness": "partial"
  },
  "lead": {}, "collaborators": {}, "tasks": [], "members": [], "attempts": [], "sessions": [],
  "reminders": []
}
```

`run`、`lead`、`collaborators` 是 Run、负责人和协作者小计三个范围，`tasks`、`members`、`attempts`、`sessions` 是其余四个维度；`text` 是一行摘要，`reminders` 是只读提醒，每条带 `kind` 和它的数字：`tokens`（`total`、`threshold`）、`oneTask`（`task`、`total`、`share`）、`idleTeam`（`collaborators`、`minutes`）、`costUnknown`，文字由应用按界面语言写。`tokens` 的每一项是 `null` 或数字；`completeness` 是 `missing`、`complete`、`partial`；`cost.lines` 为空表示「未上报」，每条带 `currency`（空字符串表示未标注）、`amount` 和 `sessions`；`durationMs`、`waitMs` 没有记录时是 `null`，不是 0。规则见[用量口径](20261031-events.md#usage_accounting)。应用在读入 Run、每批新事件之后和回放位置改变时读它（回放时带 `until`），账本只在服务端算一份。

<a id="sse"></a>
### 事件流

`GET /api/runs/{id}/stream?after=<seq>` 是 SSE：

1. 先发送 `seq > after` 的历史事件，再持续发送新事件。订阅发生在读取历史之前，两者之间不会漏事件。
2. 每条消息的 `data` 是一个事件的 JSON。
3. 服务端广播缓冲溢出时，发送 `event: lagged`。客户端收到后应重新读取 `GET /api/runs/{id}`。

### 导出

`GET /api/runs/{id}/export` 返回 `application/x-ndjson`，每行一个事件，文件名 `janus-<id>.jsonl`。

<a id="run_actions"></a>
## Run 操作

```http
POST /api/runs/{id}/actions
Content-Type: application/json

{ "type": "answer", "key": "q-T2-1-0", "task": "T2", "answer": "alpha", "commandId": "...", "expectedSequence": 128 }
```

通用字段：

| 字段 | 说明 |
| --- | --- |
| `type` | 操作类型，见下表 |
| `commandId` | 可选。同一个 Run 内每个 `commandId` 只执行一次：执行前先占用（`claim_command`，状态 `running`），操作生效后记为 `done`，失败时释放这个 id，可以带它重试。之后带同一个 id 的请求不再执行：操作已生效时返回 `{"ok": true, "duplicate": true, "commandId": ...}`；还在执行（包括同时到达的请求）时返回 409；服务在执行中途退出的，重启后记为 `interrupted`，返回 409 并说明无法确认是否生效，调用方查看事件后换一个 `commandId` 重试 |
| `expectedSequence` | 可选。与 Run 当前最大 `seq` 不一致时返回 409，客户端应刷新后重试 |

成功返回 `{"ok": true}`。Run 不存在时返回 404；Run 当前的状态不允许这个操作时返回 409（`expectedSequence` 不一致、Run 已中断而操作要求它正在运行、Run 正在运行却要求从中断处继续）；其他错误返回 400，包括不认识的 `type` 和类型不对的字段（例如 `allow` 不是布尔值、`via` 不是 `mode` 或 `config`、`action` 不是 `accept`、`decline`、`cancel`），这时请求在占用 `commandId` 之前就被拒绝。请求体按 `ActionRequest` 读取，操作是带标签的枚举 `RunAction`，处理逻辑在 `App::request_action`。

| `type` | 其他字段 | 说明 |
| --- | --- | --- |
| `answer` | `key`、`task`、`answer`、`note` | 回答提问；回答负责人用 `ask_user` 提的问题时 `task` 为空 |
| `approve` | `key`、`task`、`allow`、`option`、`label` | 处理审批请求，`option` 是 Agent 给出的 `optionId` |
| `input` | `key`、`task`、`action`、`content` | 处理表单请求，`action` 是 `accept`、`decline` 或 `cancel` |
| `message` | `text`、`images`（可选，见[图片](#images)），`agent` 或 `task` | 给会话发消息，`text` 和 `images` 至少有一个；Run 已中断时先恢复。已交付和已验收的 Run 作为普通对话继续；服务重启后第一次发消息会重新打开负责人会话（能加载原会话就加载，否则新建会话并带上简要上下文），不重跑已有任务。`text` 中的 `@路径` 作为文件引用交给 Agent，见 [ACP 集成](20261031-acp_integration.md#methods) |
| `control` | `id`、`value`、`via`（`mode` / `config`，默认 `config`），`agent` 或 `task` | 切换打开着的会话的模型、推理强度或模式；`id` 或 `value` 为空时拒绝；会话没有打开时报错。见[会话中切换控制项](20261031-acp_integration.md#session_controls) |
| `interrupt` | `agent` 或 `task` | 打断当前一轮 |
| `takeover` | `agent` 或 `task` | 接管会话，Agent 每轮结束后等用户消息 |
| `release` | `agent` 或 `task` | 交还托管 |
| `finish` | `agent` 或 `task` | 以当前结果结束会话 |
| `pause` / `resume` | 无 | 暂停时进行中的尝试继续完成，不再启动新任务；暂停的 Run 让出派发队列的槽位。只在 `planning`、`running` 时有效 |
| `start` | 无 | 让排队的 Run 立即开始，不等空位。只对 `queued` 的 Run 有效 |
| `cancel` | 无 | 取消 Run，终止所有会话；排队的 Run 取消后不再开始。交付过的 Run（结果已在用户的分支或目录里）和 `accepted`、`cancelled` 等已结束的 Run 返回错误，见[用户操作](../domains/20261031-run_lifecycle.md#user_actions) |
| `accept` | 无 | 验收，只对 `delivered` 的 Run 有效；Run 不在运行时也可以执行。在 worktree 中的 Run，结果通常在交付时已经合并回源分支（`run.merged`），验收不再提交，验收说明写明结果已在哪个提交；交付时没能合并的（用户那边挡住、冲突没解决），验收时 Janus 提交全部改动，把结果快进到创建时检出的分支（必要时先变基到最新的分支上，`risk.accepted` 的 `data.branch`、`data.commit`）；没有新的改动时不提交。变基冲突，或 worktree 里有没做完的变基、合并等操作时返回成功：用户的目录和分支不变，Janus 什么都不提交，给负责人发一条消息（`user.message`，`actor` 为 `janus`），要它在 worktree 里解决或做完并向用户说明，这一轮结束后再次交付（[ADR](../decisions/20261123-lead_resolves_accept_conflicts.md)）。失败（Git 没有配置提交身份、源分支被删除或被回退改写、worktree 里的历史被改写到不再包含起点、用户目录里未提交的改动或没纳入版本管理的同名文件会被覆盖、detached HEAD 已经移动）返回 400，错误信息说明原因、重叠的文件或结果所在的提交，Run 仍是 `delivered`，用户的目录和分支不变，见[工作目录](../domains/20261031-run_lifecycle.md#workspace_model) |
| `resumeRun` | 无 | 从中断处继续，只对 `interrupted`、`failed`、`delivered`、`accepted` 的 Run 有效；Run 正在运行时返回 409 |

排队的 Run 只接受 `start` 和 `cancel`，其余操作返回 409；刚离开队列、还在准备的 Run 也返回 409，稍后再试。

`answer`、`approve`、`input` 需要对应的请求仍在等待，否则返回 400「没有等待中的决定」。

<a id="usage_bill"></a>
## 用量账单

`GET /api/usage?from=<毫秒>&to=<毫秒>&offset=<分钟>` 汇总 `[from, to)` 里所有 Run 的用量（`backend/src/bill.rs`），供设置里的「用量账单」使用。`offset` 是用户时区相对 UTC 的分钟数，用来按用户的日期算活跃天数；区间不在 1 毫秒到 400 天之间时返回 400。

```json
{
  "from": 1760000000000, "to": 1762592000000,
  "runs": 12, "turns": 3192, "sessions": 40, "unreportedSessions": 3,
  "activeDays": 21, "days": 30,
  "tokens": { "total": 6450000000, "input": 200000000, "output": 21400000, "cachedRead": 6228600000, "cachedWrite": null, "thought": null },
  "cacheHitRate": 0.97,
  "cost": { "lines": [{ "currency": "USD", "amount": 12.5, "sessions": 4 }], "reportedSessions": 4, "missingSessions": 36 },
  "estimate": { "amount": 6389.62, "unpricedTurns": 12, "unpricedModels": ["qwen3.8-27b-mlx"], "source": "https://models.dev/api.json", "fetchedAt": 1762580000000 },
  "agents": [
    { "id": "codex", "name": "Codex", "tokens": {}, "turns": 2900, "cost": {}, "estimate": 5213.22,
      "models": [{ "model": "gpt-6-astra", "tokens": {}, "turns": 2500, "estimate": 4418.29 }] }
  ]
}
```

- 只读区间里有会话活动的 Run：有 `session.usage`、`session.prompt` 或 `agent.message` 落在区间里（按 `events_type_ts` 索引查找），所以完全没上报用量的会话也计入 `sessions` 和 `unreportedSessions`，和单个 Run 的账本一致；对每个 Run 用和 Run 账本相同的规则，只计区间里的轮次；费用取每个会话在区间结束时的累计减去区间开始时的累计。
- `agents` 按成员的运行时（Run 快照里团队成员的 `runtime` 和 `runtime_name`，例如 Codex、Claude Code）归集，每个 Agent 下按模型列出，token 多的在前。
- `turns` 是上报了 token 的轮数；`sessions` 是区间里有活动的会话，`unreportedSessions` 是其中没有上报 token 的。`cacheHitRate` 是缓存读取占输入、缓存读取和缓存写入之和的比例，Agent 没有上报缓存读取时为 `null`。
- `cost` 只有 Agent 上报的金额。`estimate` 是按 models.dev 的 API 价格算出的估算（美元），同步过价格后才有，否则为 `null`；每个 Agent 和模型的 `estimate` 是各自的部分，没有价格的模型为 `null`，它们的轮数和名字列在 `unpricedTurns`、`unpricedModels`。估算不计长上下文的加价，不是账单。

<a id="prices"></a>
## 模型价格

`GET /api/prices?models=<模型,模型>` 按会话里的模型名（逗号分隔）查 models.dev 的 API 价格（`backend/src/prices.rs`）：

```json
{
  "source": "https://models.dev/api.json",
  "fetchedAt": 1794769184902,
  "count": 2450,
  "prices": {
    "codex/gpt-6-astra": { "input": 10.0, "output": 50.0, "cacheRead": 1.0, "cacheWrite": 12.5, "provider": "openai", "official": true },
    "nonexistent-model": null
  }
}
```

- 价格是美元 / 百万 token。`official` 为 `true` 表示取自模型系列的厂商（例如 `gpt` 取 OpenAI），`false` 表示厂商没有列出、取多数提供方的价格；没有价格时为 `null`。
- 查找时取模型名最后一个 `/` 之后的部分、小写、去掉 `[1m]` 之类的后缀。
- 还没有同步过时 `fetchedAt` 为 `null`、`count` 为 0。`POST /api/prices/sync` 立即下载并返回同样的结构（`prices` 为空）。同步的时机、来源和选价规则见 [ADR：按 models.dev 的价格估算用量](../decisions/20261115-model_prices.md)。

<a id="files"></a>
## 产物读取

`GET /api/file?path=<绝对路径>` 返回纯文本。路径解析后必须是一个产物文件 `$JANUS_HOME/data/runs/<run>/artifacts/<任务>/<文件>`，或整个任务的 diff `$JANUS_HOME/data/runs/<run>/changes/<文件>`（`Layout::is_artifact`），否则返回 403；文件不存在返回 404。Janus home 的其他位置有数据库和凭据，不能通过这个接口读取。
