<a id="shape"></a>
## 形态

- 和 Mac 应用功能对齐的第二个客户端，桌面浏览器和手机都能用。它只展示：由事件推出的状态、业务规则和条目文字都由服务端（Rust）算好，见 [ADR：由事件推导的状态只在服务端算](../decisions/20261126-backend_owns_derived_state.md)。Web 只做画面自己的事：路由、折叠、草稿、语言和外观的选择、时间的写法、请求的按钮。
- TypeScript（strict）、Vite、Preact 和 `@preact/signals`，样式是自己写的 CSS，颜色、圆角和字体取 Mac 应用的同一套值（[颜色与字体](20261031-frontend.md#design_tokens)），浅色和深色都有。
- 只有 Mac 能做的不在 Web 版里：启动服务、应用更新、macOS 权限、系统通知、系统的文件夹选择框。
- 2026-11-26 的第一版有外壳（侧栏、页签、顶栏）、收件箱、工作区列表和工作区页（成员、待处理、任务记录）、对话列表、设置（语言、外观、手机访问里的这台设备）和配对页；之后有了目标的 Run 页（见 [Run 页](#run_page)）。对话页、新建目标和对话、值班、团队记忆、设置的其余部分按[加一个页面](#add_page)逐页补齐。

<a id="serving"></a>
## 由服务提供

- `backend/build.rs` 在编译时把 `web/dist` 的每个文件用 `include_bytes!` 嵌进 `janus` 二进制。没有 `web/dist/index.html` 时什么也不嵌，服务照常启动，页面说明运行 `just web` 再编译服务；所以 `cargo test` 和 CI 的编排器任务不需要 Node。构建脚本在没有构建时看着整个 `web/`、有构建时看着 `web/dist`，构建出现或变化时 cargo 会重新嵌入。
- `backend/src/http/web.rs` 是路由的 `fallback`：`/api`、`/api/…`、`/mcp/…` 中没有的接口返回 404 文字；其余路径是 `web/dist` 里的文件时返回它，否则返回 `index.html`，由客户端的路由决定显示什么。`assets/` 下的文件名带内容哈希，缓存一年（`immutable`）；`index.html` 等每次都问（`no-cache`），新构建立即生效；`assets/` 下不存在的文件返回 404，不返回页面。
- 页面和接口同源，所以页面请求不需要跨域设置。

<a id="build"></a>
## 构建

| 命令 | 做什么 |
| --- | --- |
| `just web` | `npm ci --ignore-scripts` 按 lockfile 安装依赖，`npm run build`：类型检查（`tsc --noEmit`）后由 Vite 打包到 `web/dist` |
| `just web-dev` | Vite 开发服务器，改了代码页面自己刷新；`/api` 转给 `JANUS_ADDR`（默认 `127.0.0.1:7878`）上的服务，不改 `Host`（`changeOrigin: false`），服务看到的是页面自己的来源 |
| `just test-web` | 类型检查和单元测试，不需要服务和浏览器 |
| `just e2e-web` | 浏览器端到端测试，见[端到端验证](../operations/20261031-testing.md#web_e2e) |

- `just install` 和 `frontend/scripts/package.sh` 先构建 Web 再编译服务；`just e2e` 在所有步骤之前构建一次，并设 `JANUS_WEB_BUILT=1`，打包测试不在其他步骤编译时重写 `web/dist`。
- 依赖只在构建时从 npm 下载，见[安全边界](../operations/20261031-security.md#web_build)。需要 Node.js 22.18 以上（单元测试直接运行 `.ts` 文件）。
- 源码里的 import 都写扩展名（`./api.ts`），`tsconfig.json` 开着 `erasableSyntaxOnly`：Node 的单元测试不经编译直接运行这些文件，只能用能擦除的 TypeScript 语法（不用 `enum`、参数属性）。

<a id="store"></a>
## 读服务端的状态

- `lib/store.ts` 和 Mac 的 `AppStore` 读同样的接口：`/api/meta`、`/api/setup`（Agent、数字员工、工作区、新工作区的默认团队、第一个任务前的步骤、数字员工的分组）、`/api/runs`（最新的目标）、`attention=1` 的三份列表（目标、对话、值班）、`/api/runs/workspaces`（含已删除的工作区和在干活的工作区）、`/api/loops`、看过的工作区的团队记忆、对话列表和每个看过的工作区的任务记录（`RunPager`），以及 `/api/inbox?lang=`（含按工作区归好的「等你处理」`byWorkspace`）。服务端写文字的接口都带 `?lang=`。每份都是一个 signal，读到的和原来一样时不赋值，画面不重画。
- 侧栏、工作区页和列表只读服务端给的字段，不自己判断：Run 属于哪个工作区（`workspace`）、叫什么（`title`）、状态怎么说（`label`）、哪些工作区在干活（`working`）、哪些已删除（`deleted`）、「等你处理」怎样归组和用什么颜色（`byWorkspace` 的 `label`、`tone`）、值班怎么说（`scheduleText`、`pill`、`wakesAt`、`asked`）、团队记忆怎么说（`kindLabel`、`source`、`briefLine`、`status`），见 [HTTP API](../interfaces/20261031-http_api.md)。
- 跟进用全局事件流（`lib/stream.ts`，[全局事件流](../interfaces/20261031-http_api.md#global_stream)）：`ready` 和 `lagged` 读一遍全部；`run` 读列表（派出它的值班有变化时也读值班）；`loop` 读值班；`memory` 读那个工作区的团队记忆（它的页显示过时）；`event` 是列表里还没有的 Run 时读列表，然后读收件箱；`inbox` 读收件箱；`connection` 读设置。300 毫秒内的通知合成一次读取。流断了 2 秒后重连，连上的 `ready` 再读一遍。不加定时轮询（`LESSONS.md` 的 L-28）；收件箱只在下一条推迟的回来时（`nextWake`）再读一次。
- 页面自己要的（一个 Run 的视图、值班派出的任务、资源库）在页面里读，用 `onNotice` 听流里和它有关的通知再重读。
- 换界面语言时，服务端写的文字全部按新语言重读（设置、列表、值班、看过的团队记忆、收件箱）。
- 推迟、忽略和快捷回答直接调接口（`/api/inbox/marks`、`/api/runs/{id}/actions`），之后重读收件箱；服务端再发的 `inbox` 通知让其他客户端（Mac 应用、别的浏览器）也跟上。

Mac 用弹出的表单（sheet）和浮层（popover）的地方，Web 用一页：工作区设置、共享资料、团队记忆、笔记、值班的表单都是上面的路径，宽屏上是居中的一张卡片，手机上占满屏幕。

<a id="forms"></a>
## 表单

- **工作区的目录**：网页没有系统的文件夹选择框，服务也不提供目录浏览接口（[安全边界](../operations/20261031-security.md#network_exposure)），所以新建或修改工作区时手动填目录的完整路径（可以 `~` 开头）。每次停顿 250 毫秒后问 `GET /api/inspect?path=&lang=`，显示服务端写好的那一行（「✓ Git 仓库 · 当前分支 …」「目录不存在」），目录不存在时不能保存，和 Mac 选完文件夹后的检查相同。
- **新目标的图片**：可以粘贴截图，也可以用回形针选图片（手机上是相册或相机）；每张不超过 3.75 MB、最多 10 张（服务端的限制），和目标一起发给 `POST /api/runs`。发之前先问 `GET /api/runs/preflight`，有提醒时让人确认。手机键盘上回车是换行，桌面上 ⌘↩ 或 Ctrl+↩ 发出。
- **值班的时间表**：表单只把选的样子写成 cron 表达式（同 Mac 的 `LoopSchedule.cron`），读回已有值班的样子、时间表的说法和接下来三次都由服务端给（`scheduleShape`、`GET /api/loops/schedule`）。新值班不带时区，用服务所在 Mac 的时区；改已有值班时保留它原来的时区。
- **确认**：删除、停止、放弃未保存的修改这类做了就收不回的事，先在页面里问（`lib/confirm.ts` 的 `await confirm({title, text, ok, destructive, dontAskAgain})`，`ui/ConfirmDialog.tsx` 画在外壳里），写法照 Mac 的 `confirm`：标题、后果、「取消」和写明动作的按钮（「删除」「停止」「放弃更改」），收不回的动作按钮是红色，焦点先落在「取消」，Esc 或点外面取消；删除任务带「不再提醒」，记在这个浏览器里。宽屏居中，手机从底部弹出、按钮占满一行。不用浏览器自带的 `confirm()`：它和 Mac 的样子不同，也写不出按钮的动作，端到端测试点不到。

<a id="run_page"></a>
## Run 页

目标的 Run 页和 Mac 的 `UI/Run/` 一一对应（工作台、交付的审阅、待处理、进展时间线、用量、检查器、子任务、Agent、审计与回放、团队与权限、diff 审阅、文档查看），内容全部来自服务端：

- **打开的 Run**：和会话共用 `session/model.ts` 的 `RunModel`（`pages/run.tsx` 打开它，`start()` 读记录、事件和视图并开 Run 自己的事件流，离开时 `stop()`），视图、事件和事件流只有一份。它另外记着回放位置：回放时视图（`/view?until=`）和用量（`/usage?until=`）都按那个位置读，回答对应的位置已经不是当前位置时丢掉；`seq` 不连续时整个重读。操作经 `POST /actions`，带 `commandId` 和 `expectedSequence`，409 时重读一次再试。
- **不在浏览器里算**：交付收成一行的话、复制交付摘要的文字、运行卡片的子任务进度、检查器的三栏、子任务页的执行轨迹（每行连同事件的符号名和颜色）、下游和运行环境、团队页的说明是视图的 `page`；每条 check 的一行是服务端写的 `line`、`lines` 和 `checks`；用量的每一行是 `/usage` 的 `words`。浏览器只做显示层的事：进行中的 Run 每秒把总时长那一项往后数（`usage.tsx` 的 `cardLine`，和 Mac 一样不低于记录值），时间线把没有进展的时段压成固定宽度（`timeline.tsx` 的 `TimeScale`），审计页按选中的类别、子任务和参与者筛选已读到的事件。状态的名称和颜色是界面文字，事件符号名画成哪个字符也在 `parts.tsx`。
- **会话和请求**：负责人、子任务和 Agent 的对话是 `SessionPanel`，「待处理」是 `RequestList`（服务端的 `cards`），会话卡片打开另一个会话（`run.openSession`）或 `?session=<key>` 时转到那个子任务或 Agent 的页面。对话、值班会话和整理由 `pages/run.tsx` 按 Run 的种类交给各自的页面。
- **手机**：三个视图单独一行横向滚动，文档、分享和删除在顶栏的「…」菜单里，检查器和右侧栏落到下面，时间线、代码和表格在自己的框里横向滚动，其余内容不超出屏幕（端到端测试逐个元素检查）。

<a id="i18n"></a>
## 界面语言

- 语言的选择和 Mac 一致：跟随浏览器（浏览器语言里第一个中文或英文，都没有时用中文）、简体中文、English，存在这个浏览器里。
- 界面文字用中文写在代码里：`t\`…${x}…\`` 等于 Swift 的 `L.text("…\(x)…")`，查的是同一个键：整数是 `%lld`，其他值是 `%@`，有值时文字里的 `%` 写成 `%%`；整个键在别处给出时用 `tr("键", …值)`。英文在构建时从 Mac 应用的 `frontend/Sources/Janus/en.lproj/Localizable.strings` 读出（`strings-plugin.ts` 提供 `virtual:janus-strings`），中文就是键本身，按位置的 `%1$@` 也照样填。
- 只有 Web 用的文字也加进这张表（文件末尾「The web client」一节），Mac 应用的 `LocalizationTests` 把 `web/src` 也算作用到了这些键的地方。`web/tests/strings.test.ts` 检查 Web 用到的每个中文键在表里都有英文。
- 服务端写好的文字（收件箱条目、Run 的视图）按 `?lang=zh|en` 读，换语言时重读。
- Web 的语言只决定 Web 自己的界面和它读的 `?lang=`，不改 Janus 写给 Agent 的语言：那一项只由 Mac 应用决定（`PUT /api/language`，Mac 在连上和换语言时发），Web 不发。用户在 2026-11-26 定下，免得两个客户端来回改；见 [ADR：Web 客户端](../decisions/20261126-web_client.md)第 7 条。

<a id="layout"></a>
## 布局与手机

- 宽于 640 像素：和 Mac 一样，左边是侧栏（收件箱和它的数字、团队、对话、底部的连接状态和设置），右边是页面，内容最宽 820 像素（工作区页 960 像素）居中。侧栏固定不随页面滚动，它那一栏的底色铺满整个页面的高度（画在外壳的背景上），页面比窗口长时也不断开。
- 640 像素及以下：侧栏收起，顶部是页面标题（下一级页面带返回，`usePageTitle(title, back)`），底部是四个页签：收件箱（带待处理数）、团队、对话、设置。顶栏和页签不透明（半透明加模糊时，滚动的正文会从底下透出来），并让出刘海和底部横条的安全区域（`env(safe-area-inset-*)`）；页面的大标题在手机上不显示，由顶栏代替。页面的工具（Run 页的文档、分享、删除）在手机上收进顶栏右边的「…」菜单（`usePageActions(<Menu …/>)`）。
- 横向滚动的一排（Run 页的三个视图、审计的事件类别）在藏着更多的那一边渐隐（kit 的 `useEdgeFade` 加 CSS 遮罩），不截断也不挤成两行。
- 手机上能点的东西至少 44 像素高（按钮、图标按钮、行、菜单项、折叠行）。一行放不下时，按钮换到摘要下面，不截断标题；时间这类次要信息在手机上可以不显示。
- 外观：跟随系统、浅色、深色，存在这个浏览器里，写在 `<html data-theme>` 上。
- 对话和会话在手机上占满顶栏和页签之间的高度：对话页正好一屏（`--vvh` 跟着可见视口，软键盘弹出时输入框仍在键盘上面），值班和整理的会话一屏高；输入框是一行：图片按钮、随文字长高的输入框、按钮，按钮不止一个时换到输入框下面。人在会话底部时，内容长高（Markdown、图片、发出消息后重读视图）也一直停在最新一行；视图自己滚到底不算人离开底部。
- 手机上的输入框文字 16 像素：Safari 在手机上会放大页面到任何小于 16 像素的输入框。
- 样式的先后：共用样式（`styles/tokens.css`、`base.css`、`pages.css`）在 `main.tsx` 最先引入，页面和部件自己的规则在同样的优先级下胜过 `.grow`、`.row` 这类共用类。各部分的类名不重复定义：一个全局类在两个样式文件里有两种样子时，打包后谁在后面谁就到处生效（曾经设置里每个表单字段都套上了 Run 页输入框的边框）。Run 页和会话的输入框是 `.text-field`，请求卡片的选项是 `.answer`，工作区页的新目标输入框是 `.goal-*`。
- 事件多的 Run：审计日志一次画 300 条，滚到末尾再画 300 条；会话一次画最新的 80 行，往上翻再画更早的。

<a id="plain_http"></a>
## 明文 HTTP 下可用的浏览器接口

手机经局域网或 Tailscale 地址（`http://100.x.y.z:7878`）打开 Web 版，页面不是安全上下文（只有 `127.0.0.1` 和 `localhost` 算），浏览器不提供 `crypto.randomUUID`、`navigator.clipboard`、`crypto.subtle`、Service Worker 等接口；直接调用会抛错，操作就静默失败（2026-11-27 发送消息因此在手机上没有反应）。需要这类能力时只经 `web/src/lib/plain-http.ts`：`randomId()` 用 `crypto.getRandomValues` 生成操作的 `commandId`，`copyText()` 在不能用 Clipboard API 时退回隐藏文本框加 `execCommand("copy")`。`web/tests/plain-http.test.ts` 检查别的文件没有直接用这些接口。

<a id="pairing"></a>
## 配对

服务端的规则见 [ADR：手机在局域网里扫码配对后访问 Janus](../decisions/20261126-lan_access_pairing.md) 和[安全边界：配对的设备](../operations/20261031-security.md#paired_devices)：除了本机的 Mac 应用，每个 `/api/*` 请求都要带配对得到的 cookie `janus_device`，Web 客户端的静态文件和 `POST /api/devices/claim` 不要。

- **没配对**：任何接口返回 401 时（`lib/api.ts` 记下 `unpaired`），窗口换成配对说明「这个浏览器还没有和 Janus 配对 / 请在 Mac 上的 Janus 设置 › 手机访问 扫码配对」，全局事件流停下，不再重连。
- **配对**：Mac 应用的二维码（或「在浏览器中打开」）打开 `/pair/<code>`。配对页把配对码和设备名（浏览器的设备和名字，如「iPhone · Safari」「Mac · Chrome」）交给 `POST /api/devices/claim`，成功后服务端设好 cookie（`HttpOnly`、`SameSite=Strict`），页面换到收件箱，读一遍状态并开始跟进事件流。配对码不对、用过或过期（401）、缺码（400）、别的网站发起（403）时，显示服务端给的原因。
- **403**：配对的设备不能做的（本机环境、试命令、取配对码、拨手机访问的开关）返回 403，客户端照常把服务端的文字显示在提示条里；Web 版不提供这些入口。
- **设置 › 手机访问**（`pages/pair.tsx` 的 `PhoneAccess`，对应 Mac 的 `MobileAccessView`）：列出已配对的设备（`GET /api/devices`，名字、配对于何时、最近使用），标出这台设备（`GET /api/devices/me`），只有这台设备有「取消配对」（`DELETE /api/devices/{id}`，服务端同时清掉 cookie），之后窗口回到配对说明。开关和配对二维码只在 Mac 上，这里写明去 Mac 上做。全局事件流的 `devices` 通知让列表重读。
- **被取消配对**：在 Mac 上取消这台设备时，服务端断开它的事件流；客户端在流断开后问一次 `GET /api/devices/me`，401 就换到配对说明，否则重连。

<a id="settings"></a>
## 设置

设置（`web/src/pages/settings/`）和 Mac 应用的设置面板分类相同（通用、数字员工、资源库、用量账单、手机访问）。桌面上左边是分类，右边是这一类；手机上分类列表是一页，点进去是这一类，编辑器占满屏幕（`ui/form.tsx` 的 `Sheet`）。每一行文字都是服务端写好的（见 [macOS 应用：设置页的文字](20261031-frontend.md#setup_lines)）；页面只绑定草稿、发出请求：MCP 编辑器的命令行和 JSON 每次编辑都交给服务端读写（`POST /api/library/mcp/draft`），推荐由服务端加入（`POST /api/library/picks/add`），用量账单读 `GET /api/usage/receipt`。和 Mac 不同的地方：

- **通用**：语言、外观和发送键只属于这个浏览器（记在 `localStorage`），不告诉服务端；应用更新、macOS 权限和本机环境只在 Mac 上设置，这里写明（本机环境的接口对设备返回 403）。
- **资源库**：从文件夹导入 Skill 时输入 Mac 上的路径，由服务端读取（Mac 应用用系统的文件夹选择框）。
- **数字员工**：头像选的是浏览器里的图片文件，原样上传，由服务端裁成正方形；没有「导出为文件」（它要在 Mac 上选文件夹）。
- **凭据**：Agent 的环境变量和 MCP 的值和 Mac 应用一样读出来显示、可以修改（配对的设备能读，见 [ADR：MCP 的值和 Agent 的环境变量也给配对的设备](../decisions/20261126-credentials_to_paired_devices.md)）。

<a id="session"></a>
## 会话

会话组件 `SessionPanel`（`web/src/session/SessionPanel.tsx`）照 Mac 的 `ChatCard` 画一个会话，接口是 `<SessionPanel run={RunModel} sessionKey="task:T1" title="…" />`：

- `RunModel`（`session/model.ts`）是打开的一个 Run，同 Mac 的 `RunModel`：先读 `GET /api/runs/{id}` 的事件，再读视图（`GET /api/runs/{id}/view?lang=&detail=`），然后开这个 Run 自己的事件流（`/api/runs/{id}/stream?after=&lang=`）。新事件到了 150 毫秒后重读视图，实时帧（`event: live`）原样放进 `preview`。用户手上的东西也在这里：每个会话的草稿和贴的图片，点开或收起了哪些行（`toggles`），请求卡片上选的项、补充说明和表单的填写。页面用完调 `stop()`。
- 画什么全在视图里：每个会话的 `rows`（按轮排好）和 `mode`（输入框的状态、按钮、占位文字），每条事件的一行（`lines`），请求卡片（`cards`），文件改动（`diffs`）。客户端只在 `rows` 上应用用户的点按（`session/rows.ts`，同 `Conversation.rows`），不重新分组，也不自己写事件的文字。
- 显示档位（详细、摘要）记在这个浏览器（`chatDensity`），换档位时清掉点按、重读视图。
- 会话列表先画最新的 80 行，往上翻到顶时再多画 80 行，位置不跳；在底部时跟随新内容，往上翻之后出现「回到最新」，期间有新内容写「有新消息」。
- 输入框：草稿以 `/` 开头或最后一个词以 `@` 开头时，停顿 120 毫秒后问 `GET /api/runs/{id}/suggest`，↑ ↓ 移动、Tab 或 ↩ 选中、Esc 关闭；粘贴或点回形针加图片（最多 10 张）；发送键同 Mac（`lib/sendkey.ts`：⌘↩，或在设置里改成 ↩），手机上 ↩ 换行、按按钮发送。占位文字在 `mode.keys` 为真时加上怎样贴图和发送，手机上不加。
- 等你处理的审批和表单停在输入框上方（`mode` 能发时），对话里在请求出现的位置留一行；卡片的内容（标题、来自、选项、表单字段）都是服务端写好的 `cards`，客户端只管选中、填写和发出（`POST /api/runs/{id}/actions`）。
- Agent 的 Markdown 由 `session/Markdown.tsx` 画：标题、段落、列表、引用、代码块、表格、分隔线，行内的代码、粗体、斜体、删除线和链接；只输出文本节点，不渲染文字里的 HTML，链接只放 `http`、`https` 和 `mailto`。

对话在 `pages/run.tsx` 的 `ConversationPage`：上面是数字员工和工作目录、会话结束的原因、对话里提议的数字员工（`GET /api/runs/{id}/proposal`，确认表单创建或谢绝），下面是会话。值班的会话和团队记忆的整理用 `pages/loops.tsx`、`pages/memory.tsx` 的页面，`RunPage` 把会话放进它们的 `session` 插槽；值班页旁边一栏的「待处理」是这个 Run 等你处理的全部请求（`RequestList`，同 Mac 的 `InboxSection`）。

<a id="state"></a>
## 给测试的状态出口

- `window.__janus.state()` 返回当前路由、界面语言、事件流是否连着、窗口宽度，以及每个显示着的页面「画出来的数据」（`pages.<名字>`）。和 Mac 应用的 `state` 命令一样，端到端测试拿它和服务端的返回逐项比较，不以「截图画出来了」代替。
- 页面用 `useDrawn("名字", () => ({…}))` 登记：返回的是页面实际画的东西（条目的键、标题、按钮的文字、分组），不是重新算一遍的数据。页面离开时自动撤销。

<a id="add_page"></a>
## 加一个页面

1. 先读 Mac 应用的对应视图（`frontend/Sources/Janus/UI/…`），照它的内容、顺序、交互和文案做，不另起设计。Mac 里还在 Swift 算的东西，先按 [ADR 的迁移顺序](../decisions/20261126-backend_owns_derived_state.md) 搬到服务端，两个客户端再读，不在 TypeScript 里再写一遍。
2. 在 `web/src/pages/` 加文件（相关的页面可以放在一起），样式放在同名 `.css` 里并在页面文件里 import；用 `ui/kit.tsx` 的部件，缺部件时照 `UI/Components.swift` 加到 kit 里，不在页面里另画一套。图标按 SF Symbols 的名字加到 `ui/Icon.tsx`。
3. 在 `lib/router.ts` 的 `Route` 和 `match` 里加路径，在 `main.tsx` 的 `Page` 里接上；手机上属于某个页签的页面用 `usePageTitle(标题, 返回的路径)`。
4. 页面自己的数据在页面里读（`api.get`），要跟进的用 `onNotice` 听全局事件流，或像 Mac 的 `RunModel` 那样开这个 Run 自己的流；全局共用的才放进 `store.ts`。
5. 界面文字写成 ``t`…` ``，Mac 应用里已有的文字用同一句；新的加进 `Localizable.strings` 末尾的 Web 一节。
6. 用 `useDrawn` 登记画出的数据；在 `web/e2e/` 加测试：页面数据和服务端结果逐项比较，桌面和手机宽度各截一张图，点的操作到达服务端。`e2e/web.py` 的 `prepare` 准备测试要的 Run。
7. 窄屏检查：640 像素以下不横向滚动，按钮不小于 44 像素，长文字换行或省略。
8. 跑 `just test-web` 和 `just e2e-web`，看一遍截图（桌面、手机、深色），再跑 `just e2e`。
