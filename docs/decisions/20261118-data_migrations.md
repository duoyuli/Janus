# ADR：数据随版本自动升级

- 状态：已采纳（accepted），记录于 2026-11-18。
- 相关文档：[数据升级](../architecture/20261031-data_model.md#migrations)、[默认角色：产品上线团队](../domains/20261031-agents_and_roles.md#product_launch_roles)、[与 Janus 服务的关系](../architecture/20261031-frontend.md#server_process)、[升级](../operations/20261031-deployment.md#upgrade)、[数据升级测试](../operations/20261031-testing.md#upgrade_tests)。

## 背景

`janus.db` 的表只用 `CREATE TABLE IF NOT EXISTS` 创建，设置对象和 Run 快照以 JSON 保存，没有任何版本记录。删除数字员工的「定位」字段后，老用户的数据仍带着它，只有重新保存时才消失；默认数字员工只在首次启动时写入，改进后的默认职责和指令到不了老用户，也分不清用户有没有改过。用户要求：每次版本升级里改了数据结构（加字段并给默认值、删字段、改名），都在升级时一并自动完成。同一天还出现了已安装的新版应用连上旧版服务的情况：升级根本没有执行，界面也没有提示。

## 决策

1. **数据版本**：`janus.db` 用 `PRAGMA user_version` 记录数据版本。发布中凡是改变存储内容的改动（表结构、设置对象或 Run 快照成员的字段、默认数字员工），在 `backend/src/migrations.rs` 的 `MIGRATIONS` 末尾加一条迁移。迁移由声明式步骤组成：`Sql`、`Add`（新字段和旧数据取的默认值）、`Drop`、`Rename`，其他情况用 `Custom` 函数。
2. **升级在服务启动时自动执行**：服务打开数据库时依次执行缺少的迁移，每条在一个事务中完成并写入版本号。有数据的库先用 `VACUUM INTO` 备份到 `<Janus home>/backups/janus-v<旧版本>-<毫秒时间>.db`，保留最近 5 份。迁移失败时回滚，服务不启动。应用内更新、覆盖安装和 `just install && just restart` 都因此在第一次启动新版本时完成升级，不需要单独的升级脚本。`janus migrate --dry-run` 在副本上预览升级会改什么。
3. **只读最新结构**：迁移把旧数据一次改成新结构，读取代码不保留任何旧结构的分支，与「不写兼容代码」的约定一致。默认值写进数据库，不靠读取时的 `#[serde(default)]` 补。事件是历史，不迁移。
4. **拒绝更新版本的数据**：数据版本高于这个版本的 Janus 支持的版本时，服务拒绝启动，提示升级 Janus 或从备份恢复，避免旧代码写坏新数据。
5. **默认内容按「改没改过」更新**：默认数字员工记录来源和拿到的文本的哈希（`seed`）。启动时，没改过的职责和指令换成当前版本的默认文本；改过的保留，编辑器提示有新版并让用户选择「采用新版」或「保留我的」。删除的默认数字员工不会恢复。没有 `seed` 的老数据由迁移按历次发布过的文本判断是否改过。
6. **漏写迁移由测试拦下**：每类存储对象登记字段（`data_shape.rs`，结构体按读回再写出必须不变检查），测试中每次 `put_config` 都按登记的字段检查；表结构和登记的字段记在 `backend/testdata/data_shape.json`，与迁移版本一起变化，变了而没有新迁移时测试失败。旧版本真实写出的数据（`backend/testdata/upgrade/`）升级后必须全部符合当前结构。`just e2e-upgrade` 从最近几个发布标签的源码构建旧版服务写入数据，再用当前版本升级并逐项核对。
7. **版本握手**：服务在 `/api/meta` 报告发布版本（打包时的 `JANUS_VERSION`）和数据版本。安装包里的应用连上一个不是自己启动、版本又不同的服务时，不使用它，提示并提供「停止旧服务并重试」。

## 取舍

- **与单独的升级脚本相比**：应用内更新替换应用后直接重新打开，没有让用户运行脚本的环节；放在服务启动时，任何安装方式都会执行，也不会漏。代价是迁移有问题时服务起不来，所以先备份、失败即回滚并提示备份位置。
- **与读取时兼容旧结构相比**：读取代码只有一份，旧结构的处理只存在于某一条迁移中；代价是每次改结构都要写迁移，由测试强制。
- **默认内容不强制覆盖**：保护用户的修改；代价是改过的用户需要自己选择一次。
- **字段登记**：手写 JSON 的对象（连接、数字员工、工作区）需要人工登记字段，结构体对象自动检查。登记不全时测试中的写入会失败，所以不会悄悄漏掉。

## 后果

- 第 1 版迁移删除数字员工和 Run 快照成员的「定位」，以及成员的模型标签；第 2 版为默认数字员工记录来源。
- 新增 `<Janus home>/backups/`；目录规范和安全边界文档已更新。
- 合并前检查新增规则 11：改了存储的数据，必须带迁移和测试。
- 以 `just dev` 运行的服务报告 crate 版本（`0.1.0`），安装包里的应用会把它当作其他版本，提示停止它。从源码运行的应用（版本 `0`）不做这个检查。
