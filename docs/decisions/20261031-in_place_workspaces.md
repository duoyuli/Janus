# ADR：任务直接在工作目录中运行

- 状态：Git 仓库的部分已被 [ADR：Git 仓库上的每个任务在自己的 worktree 中运行](20261119-run_worktrees.md) 取代（superseded，2026-11-19）；非 Git 目录仍按本 ADR 直接在工作目录中运行。
- 相关文档：[Run 生命周期](../domains/20261031-run_lifecycle.md#workspace_model)、[数据模型与存储](../architecture/20261031-data_model.md#artifacts)、[安全边界](../operations/20261031-security.md#workspace_access)。

## 背景

早期每个写任务在独立的 Git worktree 中运行，完成后由编排器提交到分支，多个写任务再由集成任务合并；只读任务在只读快照中运行，非 Git 目录则所有成员只读。用户要求：不要和 git worktree 绑定，现在直接在当前目录下改就行，需要 git worktree 时再迭代。

## 决策

1. 关闭独立 worktree。
2. 负责人和所有任务都在工作区目录中运行，改动立即彼此可见；Janus 不提交、不推送。
3. 非 Git 目录也可以运行写任务，只是没有 diff 产物。
4. Git 仓库中，尝试结束时保存相对 `HEAD` 的未提交改动作为 diff 产物；目标模式从 Run 开始时的状态算起，只记录 Run 期间新增的变化。
5. 最初把 worktree、集成任务和只读快照的代码留在编译期开关 `ISOLATED_WORKTREES` 后面；2026-10-30 清理代码时连同开关一起删除，以后需要时重新设计。

## 取舍

- **与独立 worktree 相比**：没有分支合并和冲突处理的开销，负责人和协作者能立即看到彼此的改动，非 Git 目录也能工作；代价是并行写任务可能修改同一批文件，负责人需要用依赖把会冲突的任务串行，并且 Janus 无法按任务回退改动。
- **diff 是整个工作目录的**：同时运行的多个任务的改动会出现在同一份 diff 里，不能精确归属到某个任务。

## 后果

- 界面和负责人说明都明确告知任务会直接修改目录。
- 以后重新引入 worktree 时，需要重新设计集成任务、diff 归属和恢复逻辑。
- 2026-11-12 起，diff 产物限定在任务负责和改过的文件，只有两样都没有记录时才是整个工作目录的 diff，见 [ADR：协作者认领文件，Janus 读回工作目录里的痕迹](20261113-claims_and_traces.md)。
