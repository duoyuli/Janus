# ADR：断掉的会话回到原处继续

- 状态：已采纳（accepted），记录于 2026-11-25。
- 相关文档：[Run 生命周期：重试、返工与失败](../domains/20261031-run_lifecycle.md#retry)、[一次尝试](../domains/20261031-run_lifecycle.md#attempt)、[目标模式：失败处理](../domains/20261031-goal_mode.md#failures_in_goal_mode)、[ADR：热会话续接](20261118-session_continuation.md)、[ADR：服务重启后自动继续](20261125-continue_after_restart.md)。

## 背景

会话会因为与工作本身无关的原因断掉：Agent 进程退出、服务商返回错误（例如代理 120 秒读超时的 524）、连接中途断开。2026-10-28 至 11-24 的记录中，这类失败的处理方式各不相同：

- **协作者的尝试**：3 秒后新开会话重试，发完整的任务提示。之前读过的文件、做到一半的推理全部丢掉，从头再来；新会话的冷启动（读文档、熟悉任务）中位约 3.3 分钟才开始第一次编辑。3 秒也太短：11-02 两次重试都撞上同一次服务商故障，任务失败，负责人 2.5 分钟后才重新派出。
- **负责人**：会话一断，Run 在没有任务执行时直接失败，等用户点「从中断处继续」。没有人看着时（值班派出的 Run），工作就停在这里。

服务重启的情况已经解决：中断的尝试和负责人都加载原会话，被告知发生了什么后接着做。会话因故障断掉，和因重启断掉没有本质区别，会话本身（Agent 自己保存的记录）仍然完好。

## 决策

1. **协作者的重试回到原会话**：尝试失败、还有剩余次数时，Janus 记下这个任务最近打开的会话和失败原因（`Reload` / `BrokeOff::Failure`，与任务回到 `pending` 在同一把锁里）。下一次尝试 `session/load` 这个会话，提示只写「上一次因为某原因中断，之前做过和读过的都还在，从中断的地方继续，不要重做」。
2. **满了的会话不回去**：原会话上下文超过 75%（和负责人 `retry` 选 `continue` 的界限相同），或 Agent 不支持加载、加载失败、这个任务从没打开过会话时，新开会话，按原来的方式发完整任务提示并附上失败原因。回不去的原因记在 `attempt.started` 的 `data.continuation`。重启打断的会话照旧不看上下文占用：它在重启前工作正常。
3. **重试前等 30 秒**（`RETRY_AFTER`）：给服务商的短暂故障留出恢复时间。工作没有时间上限，30 秒相对一次尝试（中位 7.4 分钟）可以忽略。
4. **负责人断了也回去**：负责人会话在目标完成之前出错，等同样的 30 秒后走重启恢复的同一条路径（`lead_goal` 带 `LeadResume`）：加载原会话，提示写明会话为什么断了、协作者一直在继续、现在的看板状况；加载不了就新开会话。`lead.failed` 的 `data.next` 写明 `reopen` 或 `stop`。
5. **防止反复重开**：负责人重新打开后没有做任何事（说话、调用工具、编排）就又断了，或者 Agent 拒绝了 `/goal`，不再重开，按原来的规则处理（没有任务执行时 Run 失败，等用户）。协作者的重试次数仍由 `MAX_ATTEMPTS` 限定。

## 取舍

- **不区分故障类型**：Janus 拿到的错误文本来自不同的适配器和服务商，按文本分类既不完整也会过时。回到原会话对任何故障都不比新开会话差；会话本身坏了时，加载失败或超过 75% 会自然退回新会话。
- **不为额度和限流单独处理**：同一时期的记录中没有一次编码 Agent 的会话碰到额度或限流，等真的出现、知道它怎样暴露之后再定。
- **用「有没有进展」而不是次数限制负责人的重开**：一次性的故障可能出现多次，每次之后负责人都在推进，不应该因为累计次数被停下；连续断掉而毫无进展，才说明问题不会自己消失。
- **协作者回到原会话不改变尝试次数**：一次失败仍然算一次尝试，任务的最多尝试次数不变，失败两次后照常交给负责人。

## 后果

- `resume_session` 从「会话 id」改为 `Reload`，重启恢复记为 `BrokeOff::Restart`；负责人看到的恢复看板分别写明「重启时正在执行」和「上一次尝试断了，回到原会话继续」。
- `task.retry_scheduled` 的 `data.strategy` 改为「回到原来的会话从中断处继续；回不去时新建会话…」。
- 流程测试覆盖：协作者失败后加载原会话并收到原因、满了的会话退回新会话、负责人断开后回到原会话并交付、连续断开且没有进展时停下。
