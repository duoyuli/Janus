# ADR：自动更新

- 状态：已采纳（accepted），记录于 2026-11-23。
- 补充：[ADR：应用内增量更新](20261102-in_app_updates.md)：在同一条下载、校验和替换路径上加上「不用点击，空闲时自动装上」。
- 相关文档：[macOS 应用：自动更新](../architecture/20261031-frontend.md#auto_update)、[安全边界：应用更新的来源](../operations/20261031-security.md#app_updates)。

## 背景

应用内更新原来只提醒：发现新版本后在侧栏显示「可以更新」，用户点「更新到 <版本>」才下载、替换并重开。用户希望检测到新版本就自动下载，在没有任务在执行时直接升到最新版本，并在「设置 › 通用」里可以打开或关掉。

## 决策

1. **默认打开，可以关掉**：「设置 › 通用 › 更新」最上面加「自动更新」开关，记在应用自己的偏好设置里（`janus.autoUpdate`），不进服务的设置：它只关乎这台机器上的这个应用。
2. **发现就下载**：检查发现新版本时，立即按原来的流程下载变化的部分、核对 SHA-256、拼装、校验签名和签名者，然后停在 `ready`，不立即重开。
3. **空闲时换上**：每 30 秒看一次有没有任务、对话或值班在进行，用和退出确认相同的列表（`AppStore.working`）；连续两次都没有才替换并重开，刚开始、还没出现在列表里的任务不会被打断。用户随时可以点「现在更新」立即换上。
4. **关掉时和原来一样**：只提醒，由用户点击安装；等待中关掉开关就不再等，已下载的版本留着。

## 取舍

- **默认打开**：Janus 每天都可能发布修复，用户要的是始终在最新版本；校验和签名者要求不变，自动装上的和手动点击装上的是同一个包。
- **只看任务和对话，不看用户是否正在操作**：这是用户给的条件；重开后窗口和服务都会回来，正在输入但还没发出的文字可能丢失。真遇到时再加「用户一段时间没有操作」的条件。
- **复用退出确认的列表**：「会被打断的工作」只有一个定义，退出和更新判断一致。

## 后果

- `Updater.State` 多了 `ready`；`Updater` 多了 `automatic`、`isBusy` 和 `installStaged`。
- 签名证书泄露的影响变大：攻击者签出的版本会被自动装上，而不是等用户点击，写进[安全边界](../operations/20261031-security.md#app_updates)作为明确接受的风险。
