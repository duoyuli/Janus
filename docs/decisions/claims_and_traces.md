# ADR：协作者认领文件，Janus 读回工作目录里的痕迹

- 状态：已采纳（accepted），记录于 2026-11-12。
- 相关文档：[工作目录里的痕迹](../domains/goal_mode.md#traces)、[团队结构](../domains/goal_mode.md#team_structure)、[同时改同一个文件](../domains/goal_mode.md#conflicts)、[`claim`](../interfaces/board_mcp.md#claim)、[ADR：通过 MCP 看板协作](board_over_mcp.md)、[ADR：任务直接在工作目录中运行](in_place_workspaces.md)。

## 背景

团队协作有两种对齐方式。一种是看板：每个成员把做了什么、打算做什么写下来，其他人读看板。另一种像蚂蚁：成员直接改环境，后来者从环境里看到前人做了什么，再调整自己的行为。

Janus 的协作者都在同一个工作目录中工作，工作目录本身就是最可靠的记录。看板上的自我汇报会和实际情况脱节（说做完了，工作目录里没有改动；说改了 A，实际改的是 B），而且汇报越多，主控的上下文消耗越大。反过来，只靠环境也不够：痕迹只能在事后出现，等看到别人的改动，冲突已经发生；diff 只说明改了什么，不说明为什么、别人要不要跟着调整；验收和取消是决定，不是行为。

此前的实现两边各有缺口：

- `owns` 只能由主控在编排时划定，协作者做起来才发现要改的文件，只能写 blocker 等主控。
- 改了别的任务负责的文件，要等对方也改了同一个文件才报告。
- diff 产物是整个工作目录的，并行任务的改动混在一起，验证者读到的「它的改动」并不准确。
- 下游任务只拿到上游的结果摘要，不知道上游改了哪些文件，也不知道这些文件之后又被改过。
- 每个任务改过的文件只在内存中，重启后冲突检测和 `peers` 从头开始。

## 决策

1. **分工**：看板只放读不出来的东西：动手前的承诺（`owns`、认领）、意图和理由（`board_post`、`amend`）、裁决（`accept`、`cancel`、`ask_user`）。能从工作目录读出来的事实由 Janus 读回，不要求协作者汇报。
2. **认领**：协作者用 `claim` 在动手前认领文件，写 `task.claimed`，认领并入任务的 `owns`，到任务结束为止有效。已归另一个可能同时执行的未结束任务负责的文件不能认领；验证任务不能认领。
3. **越界立即报告**：任务改了另一个可能同时执行的未结束任务负责的文件，Janus 立即写 `task.conflict`（`data.owned: true`），提醒越界的一方停下。
4. **结果与痕迹对账**：任务完成时，Janus 拿它负责的文件、改过的文件和工作目录相对 `HEAD` 的改动对账，不一致写进 `task.succeeded` 的 `data.traceGaps` 并推送给主控。
5. **diff 只含自己的文件**：diff 产物限定在任务负责和改过的文件。
6. **标出可能过期的结论**：上游完成后它改过的文件又被别的任务改了，下游提示、`task_detail` 和 `peers` 中标出，要求以工作目录的现状为准。
7. **痕迹从事件重建**：改过的文件来自 `tool.call` 的 `data.paths`，重启后由 `resume_run` 重建。

## 取舍

- **认领由协作者发起，而不是只由主控划定**：主控事先猜不全每个任务要改的文件；让协作者在动手时认领，承诺仍然发生在改动之前。代价是认领不经过主控批准，主控只在看板上看到「[认领]」。冲突的认领会被拒绝，所以不会出现两个同时执行的任务负责同一个文件。
- **不阻止越界，只报告**：权限由 Agent 原生模式决定（见 [ADR：权限交给 Agent 原生模式](agent_native_permissions.md)），Janus 不拦截文件写入，只提醒和报告。
- **对账只核对能确定的事**：没有 `owns` 的任务除了验证者都不核对，因为不知道它应该改什么。用命令改文件不会出现在工具调用中，所以对账同时看 Git 的工作目录状态，避免误报；不是 Git 仓库时只能看工具调用，提示中写明可能是用命令改的。
- **过期判断以工具调用为准**：只知道哪个任务通过工具调用改了文件，用命令改的不计入。

## 后果

- 新增事件类型 `task.claimed`，`task.conflict` 多了 `data.owned`，`task.succeeded` 多了 `data.traceGaps`，`context.handoff` 多了 `data.files` 和 `data.stale`。应用的 `derive` 和 `boardFacts` 已同步。
- 协作者的看板工具多了 `claim`，主控说明和任务提示中加了认领和对账的说明。
- 不扩大信任边界：没有新的下载来源、网络监听或用户目录读写，Git 查询仍走只读入口（`git_probe`）。
