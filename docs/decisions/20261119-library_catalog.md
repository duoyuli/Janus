# ADR：资源库的精选库随应用发布，一键添加

- 状态：已采纳（accepted），记录于 2026-11-19。
- 相关文档：[资源库](../domains/20261116-resource_library.md#catalog)、[安全边界](../operations/20261031-security.md#library)、[macOS 应用](../architecture/20261031-frontend.md#screens)、[ADR：资源库默认给所有数字员工](20261119-library_routing.md)。

## 背景

用户要求在资源库的 Skill 和 MCP 标签里各加一个「精选库」，把社区里常用的 Skill 和 MCP 服务器做成快捷入口，一键添加，参照 magpie 的做法。magpie 的精选分三部分：自己挑选并逐个核对过的服务器（写在代码里）、运行时拉取的 MCP Registry，以及运行时从 skills.sh 读取的热门 Skill。Janus 推荐具体的第三方仓库和软件包，扩大了信任边界，按合并前检查第 5 条单独记录。

## 决策

1. **只有写在代码里的精选**：列表在应用的 `Catalog`（`frontend/Sources/Janus/Core/Catalog.swift`）中，随版本发布，显示精选不访问网络。不接 MCP Registry 或 skills.sh 这类运行时目录，不新增下载来源。
2. **挑选标准**：每个 Skill 的目录在它的 GitHub 仓库中存在（核对过仓库的文件树）；每个命令启动的服务器的 npm 或 PyPI 包已经发布；每个 HTTP 服务器的地址能回答 MCP 的 `initialize`（需要令牌的返回 401）；不收需要 OAuth 登录的服务器，因为 Janus 不能替服务器完成登录。
3. **添加 Skill 走 Git 来源**：等同于用户粘贴仓库链接后勾选这个 Skill。已经有整个仓库的来源时直接从中导入，否则先添加仓库来源（克隆默认分支），再导入。导入的 Skill 和其他 Skill 一样默认给所有数字员工。
4. **添加 MCP 服务器走 MCP 编辑器的同一个接口**：不需要填值（或只有可选的值）的服务器一键添加；需要 API key 的，打开预填好的 MCP 编辑器，写明去哪里拿 key。新服务器和其他服务器一样默认只给选中的数字员工。
5. **不锁版本**：命令启动的服务器用 `npx -y <包>@latest` 或 `uvx <包>` 运行最新版本，Skill 跟随仓库默认分支，和这些项目自己的 README 写法一致。

## 取舍

- **不锁版本**：锁定版本要靠 Janus 发版更新精选，而已经添加的资源也不会随精选更新；跟随最新版本和用户自己照 README 添加时一样。代价是包或仓库被篡改时，下一次启动或更新会拿到被篡改的内容。Skill 的来源可以「检查更新」后再决定是否更新；MCP 包没有这一步。
- **不接运行时目录**：选择少一些，但列表里每一项都核对过，也不需要信任第三方目录的内容和排名。

## 后果

- 资源库的两个标签最下面各有一块「推荐」（排在路由说明和已添加的资源之后），已经在资源库里的项标为「已添加」。
- 安全文档的「资源库」一节写明精选是第三方内容、不锁版本。
- 精选的内容随应用版本更新；增删一项时重新核对上面的挑选标准。
