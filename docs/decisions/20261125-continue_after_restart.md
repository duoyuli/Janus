# ADR：服务重启后，进行中的目标 Run 自动从中断处继续

- 状态：已采纳（accepted），记录于 2026-11-25。
- 相关文档：[Run 生命周期：中断与恢复](../domains/20261031-run_lifecycle.md#recovery)、[派发队列](../domains/20261031-run_lifecycle.md#dispatch_queue)、[工作区值班](../domains/20261121-loops.md)、[ADR：所有目标 Run 经过一个派发队列](20261121-dispatch_queue.md)。

## 背景

服务重启（应用更新、退出后重开、崩溃、机器重启）时，进行中的目标 Run 记为 `interrupted`，要等用户点「从中断处继续」或给某个 Agent 发消息才接着做。用户在电脑前时这不是问题：2026-11-15 至 11-24 的 23 个目标 Run 中，被中断的 Run 中位约 6 秒后就被用户继续了。

值班把这个前提打破了。值班按时间表醒来、派出 Run，没有人看着；服务重启后值班照常醒来，它派出的 Run 却一直停在「已中断」，派发记录上它们没有结束，值班也不会因为它们结束而醒来。同一时期有 5 个目标 Run 中断后再也没有继续。工作台要能无人值守地消化任务，一次重启就让所有进行中的工作停下等人，是内核层面的缺口。

负责人和协作者恢复后都加载原来的会话、收到重启时的看板状况（见[中断与恢复](../domains/20261031-run_lifecycle.md#recovery)），从中断处继续已经不会从头做，缺的只是「谁来按下继续」。

## 决策

1. **目标 Run 自动继续**：服务启动时（`recover`），状态是 `planning` 或 `running` 的目标 Run 照常记为 `interrupted`，`run.interrupted` 的 `data.after` 写明之后怎样（`AfterRestart`）。服务开始监听后（`continue_after_restart`），`after` 为 `goes_on` 的 Run 逐个按「时间表」的身份（`Asker::Schedule`）继续，和用户点「从中断处继续」走同一条恢复路径；`run.recovered` 的 `actor` 是 `janus`，`data.auto` 为 `true`。
2. **先还槽位，再派新的**：自动继续的 Run 在重新开始之前就算作在做（`App.continuing`），补位不会把它们的槽位先交给排在队列里的新 Run。
3. **两种情况等人**：
   - 重启前用户暂停了它（最后一次继续之后有 `run.paused`，之后没有 `run.resumed`）：`after` 为 `paused`。
   - 上次重启后它已经自动继续过，而在这次重启之前没有任何 Agent 做过事（说话、调用工具、交结果、编排、完成子任务，`EventKind::is_agent_progress`）：`after` 为 `no_progress`。这样一个让服务停下的 Run 不会在每次启动时被反复拉起。
4. **其他类型不变**：对话和值班的会话在下一条消息或下一次开工时打开；整理团队记忆只有一轮。它们的 `after` 为 `person`。自动继续失败时（工作区不在、Agent 不能运行），Run 保持中断，再记一条 `run.interrupted` 写明原因，等用户处理。

## 取舍

- **不加开关**：「重启后要不要接着做」不是用户每次需要判断的事。值班派出的和用户自己提交的目标一样处理；不想让某个 Run 继续，暂停或停止它即可。
- **用「之后有没有进展」防反复，而不是计次数**：次数上限会把一个正常被多次重启的长 Run 也停下来；只看「自动继续之后到这次重启之间有没有 Agent 做过事」，判断的是这个 Run 本身是否可能是重启的原因。
- **逐个继续**：恢复要重建 worktree、读回看板、打开会话，逐个做避免启动时同时拉起所有负责人；Agent 进程的座位按「时间表」排，用户在等的会话仍然优先。
- **中断仍然记录**：`run.interrupted` 和 `run.recovered` 都写进事件日志，Run 的时间线照常显示「中断」和「自动继续」，用量账本和恢复逻辑不需要区分两种继续。

## 后果

- 应用退出和更新的确认文案改为「下次打开 Janus 时，任务自动接着做」。
- 收件箱里「已中断」的目标 Run 只剩暂停过的、自动继续没有进展的和自动继续失败的。
- `restart` 端到端场景验证：进行中的 Run 不经操作自动继续并交付，暂停的 Run 等用户继续。
