# ADR：先出计划、用户确认、再按 DAG 执行

- 状态：已取代（superseded）。被 [ADR：主控以 /goal 推进目标](goal_mode_lead.md) 取代，记录于 2026-10-30。
- 相关文档：[Run 生命周期](../domains/run_lifecycle.md#early_plan_runs)。

## 背景

Janus 最早的流程是：主控只读阅读工作目录，输出一份带依赖、执行者、重试和验证策略的 JSON 计划；用户确认（可以调整执行者）后计划冻结，编排器按 DAG 调度；评审任务可以驳回并要求返工；必需任务失败时停下来等用户决定。

## 决策

1. 每个 Run 先规划，计划必须通过 Janus 的校验并经用户确认后才执行。
2. 执行完全由编排器按计划推进，主控在规划后不再参与。
3. 提问、任务失败都交给用户。

## 取舍

- 计划在执行前可审阅，执行过程完全可预测。
- 但无论目标大小都强制拆分和协作，主控不能根据执行中的发现调整，用户需要在开始前确认，在过程中处理所有提问和失败。

## 后果

- 取代后，这套流程先保留为计划模式（`mode: "plan"`），只用于测试和回放旧 Run；2026-10-30 清理代码时删除。旧 Run 的事件仍可查看，但不能继续。2026-11-01 应用中针对这些 Run 的计划、评审和任务卡片显示也已删除，只保留会话、交付和审计日志。
- 调度循环、尝试、验证和重试的实现被目标模式沿用。
