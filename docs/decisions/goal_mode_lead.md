# ADR：负责人以 /goal 推进目标

- 状态：已采纳（accepted），记录于 2026-10-30。取代 [ADR：先出计划、用户确认、再按 DAG 执行](plan_first_flow.md)。
- 相关文档：[目标模式与共享看板](../domains/goal_mode.md)、[Run 生命周期](../domains/run_lifecycle.md#delivery_conditions)、[ADR：通过 MCP 看板协作](board_over_mcp.md)。

## 背景

用户认为强制负责人先规划再执行是错误的设计。Claude Code 和 Codex 都有 `/goal` 功能：负责人应当以 `/goal` 加用户输入的目标去执行，同时被告知有哪些协作者可以帮忙；需要帮忙就把任务分配出去，不需要就自己从 0 到 1 完成，而不是强制要求它规划。目标是一个通用的 agent team。用户同时规定：只有 Claude Code 和 Codex 可以做负责人，因为只有它们有 `/goal`。委派任务不需要用户逐一确认，并允许并行执行。

## 决策

1. 默认的 Run 是目标模式：负责人会话收到说明（团队名单、看板工具、协作要点）后，执行 `/goal <目标>`。
2. 是否协作、怎样拆分由负责人决定；负责人通过看板提交编排，委派任务不需要用户确认，按依赖并行执行。
3. 负责人只能是 Claude Code 或 Codex，在保存工作区、创建 Run 和启动负责人时三处检查。
4. Claude Code 通过追加系统提示接收说明，并在其隔离配置中信任工作目录；Codex 先收到说明再收到 `/goal`，Janus 跟随它报告的目标状态。
5. 负责人的目标结束、没有任务还在执行或可以启动时交付，摘要取负责人最后一条回复；负责人会话异常结束时 Run 失败，可以从中断处继续。
6. 委派任务的失败和提问由负责人处理，不打扰用户；负责人结束后仍未回答的提问转给用户。

## 取舍

- **与先出计划相比**：简单目标不再被拆成多个任务，负责人可以根据执行中的发现调整；代价是执行前没有可审阅的完整计划，执行路径由负责人决定，可预测性下降。
- **依赖 `/goal`**：负责人的范围缩小到两种 Agent，`/goal` 的行为（例如 Claude Code 需要受信任的工作区、Codex 的目标状态）随 Agent 版本变化，Janus 需要跟进。
- **验收由负责人自行核对**：目标模式没有独立评审任务，结果质量依赖负责人的核对和用户的验收。

## 后果

- 计划模式先保留为 `mode: "plan"` 供测试和旧 Run 使用，2026-10-30 删除。
- 界面的阶段条改为「推进目标 / 协作 / 交付 / 验收」，委派任务失败不弹出用户决定卡片。
- Claude Code 负责人路径尚未在真实运行中验证；Codex 负责人已用真实运行验证。
