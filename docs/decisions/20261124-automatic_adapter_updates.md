# ADR：自动接受并安装适配器的新版本

- 状态：已采纳（accepted），记录于 2026-11-24。
- 相关文档：[ACP 适配器管理](../architecture/20261031-adapters.md#update_check)、[适配器安装的安全边界](../operations/20261031-security.md#adapter_install)、[HTTP API](../interfaces/20261031-http_api.md#adapters)、[ADR：ACP 适配器按需安装，按版本存放](20261031-on_demand_adapters.md)。

## 背景

ACP 适配器是 Agent 的底层运行组件，用户平时只关注 Agent 本身。原来的界面上，每个 Agent 卡片底部一行写「ACP 适配器 <版本> 最新 <版本> · <时间> 检查」，旁边是「切回」和「检查更新」两个按钮，侧栏底部还有「N 个 ACP 适配器有新版本」的提醒。用户的要求原话：

> 这个页面的切回 xxx 版本的这个放在这里有点奇怪，用户其实不关注这个，并且这个和检查更新放一起还有点影响用户注意力。正常情况下用户只关注 agent 就行，acp 这一层不希望有太多注意力在上面。把检查更新的按钮去掉，系统层面去自动检测并升级，在现有版本后面增加一个切回历史版本就行了，这里的 UI 和 UX 你再设计下，要用户尽可能减少注意力在上面

也就是：去掉手动检查更新，由 Janus 自己检测和升级；只保留「切回历史版本」；ACP 这一层在界面上尽量不占注意力。设计见产品侧定稿的适配器行设计与验收标准。

## 决策

1. **无人值守自动升级**：服务启动 45 秒后检查一次，之后每 6 小时一次；对已安装、没有任务在跑、没有被固定的适配器执行 `npm view <包> version`，查到比当前新的版本就在后台安装并切换。任务记为 `action: auto`。
2. **失败不打扰**：安装失败只写日志和 job 的 `error`，当前版本不变、Agent 照常可用，下一次检查重试；查询失败（离线、没有 npm）只写 Janus 日志，不产生 job，界面上不显示。
3. **固定与恢复**：用户在界面上切回一个已安装版本即固定它，版本号写在 `cache/adapters/<id>/pinned`。固定期间检查照常进行、只记录 `latest`，不安装、不切换；服务重启后从文件读回。手动 `install` 是「恢复自动更新」：先解除固定，最新版已经装过就直接切过去（离线也能恢复），没装过才下载。清理（`prune`）保留固定的版本。
4. **保留回滚**：自动升级保留切换前的版本，供「切回历史版本」菜单使用；一个版本还有会话在用时也不清理（`VersionPin`）。切换和升级只影响之后启动的会话。
5. **界面做减法**：删除手动检查更新的接口（`POST /api/adapters/{id}/check` 和 `start_adapter_check`）、按钮、侧栏提醒、最新版本和检查时间。运行组件一行只有当前版本和灰色的「切回历史版本」菜单；自动升级进行中只写「更新中…」，完成不弹 Toast 和通知，设置页开着时最多 10 分钟显示「已自动更新」，失败才在行内露出「更新没成功」和原因入口。
6. **npm 来源不变**：仍是 `@agentclientprotocol/codex-acp` 和 `@agentclientprotocol/claude-agent-acp`，安装仍带 `--ignore-scripts`，仍按版本存放；不新增下载来源。

## 取舍

- **供应链信任扩大**：无人值守地接受 npm 上的新版本，不再有人工确认这一步。沿用 `--ignore-scripts`，只执行适配器进程本身；代价是适配器包的运行时代码会自动更新，信任边界与手动执行 `npm install <包>@latest` 相同。按合并规则 5，本决策单独提交并写进[安全边界](../operations/20261031-security.md#adapter_install)。
- **坏版本风险**：安装只验证包能装上、入口文件存在，不能保证新版本行为正确。兜底是保留上一个版本、可以从菜单切回并固定；升级后不做启动探测，也不自动回滚，这超出本次范围。
- **没有开关**：按用户要求直接自动升级，没有「不自动更新」的全局设置；固定的版本本身是逐种 Agent 的暂停方式。
- **固定存在 `cache/` 里**：这是 `cache/` 中唯一跨重启有意义的状态。好处是不需要数据迁移和数据结构快照；代价是用户清空 `cache/` 会同时失去固定和旧版本，需要重新切回。固定文件很小，随适配器目录一起管理。
- **不做安装后的界面确认**：只有用户自己发起的操作（切回、恢复自动更新、重试安装）用现有 Toast 确认；自动升级完成不弹任何东西。

## 后果

- [ADR：ACP 适配器按需安装，按版本存放](20261031-on_demand_adapters.md) 第 4 条「应用提供检查更新、升级和切回已安装版本」中的检查更新和手动升级被本决策取代；按需安装、按版本存放、保留上一个版本、回滚和运行中会话不受影响这几条不变。
- 自动升级、切回固定和恢复的判定有后端单元测试；产品端到端测试的 `adapter-updates` 场景用替身 npm registry 跑真实的自动检查和 `npm install`，覆盖自动升级、切回固定、重启保留和恢复。
- 以后要调整检查频率、增加升级后的启动探测或自动回滚、或恢复手动检查入口，需要新的 ADR。
