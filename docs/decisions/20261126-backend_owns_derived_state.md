# ADR：由事件推导的状态只在服务端算

- 状态：已采纳（accepted），记录于 2026-11-26，用户在 2026-11-25 定下方向。取代 [ADR：用原生 macOS 应用做展示层](20261101-native_macos_app.md) 的第 4 条（事件推导 `derive` / `boardFacts` 在 Swift 中实现）。迁移尚未完成，见下文「迁移顺序」和 `LESSONS.md` 的未解决项。
- 相关文档：[由事件推导状态](../architecture/20261031-frontend.md#event_derivation)、[收件箱](../architecture/20261031-frontend.md#inbox)、[交付的审阅](../architecture/20261031-frontend.md#review)、[ADR：事件是唯一事实来源](20261031-events_as_source_of_truth.md)。

## 背景

应用从事件日志自己推导 Run、任务和 Agent 的状态、看板上的待办、收件箱条目和交付的审阅阶段（`Derive.swift` 的 `derive` 和 `boardFacts`、`Inbox.swift`、`Review.swift`），服务端为调度、看板和恢复也推导一份。两份在同一批事件上各算各的：2026-11-25 负责人交出的提问在交付后没被撤回，服务重启后待处理决定只剩应用推导出的卡片，点哪个选项都被服务端拒绝。用户要求事件和由事件推导的状态都在服务端 Rust 中计算、存进 SQLite，应用只展示。

用量账本已经这样做了：只在服务端算（`usage.rs`），应用读 `GET /api/runs/{id}/usage?until=`，只负责写成文字。

## 决策

1. 由事件推导的业务状态只在服务端算一份：Run、任务和 Agent 的状态，看板上等谁处理的事，收件箱条目，交付的审阅阶段和要看的信号。应用读服务端给出的结果，不再从事件推导这些状态。
2. 服务端给出结构化的事实（种类、关联的子任务和成员、数字和原文），不给界面文字；应用按界面语言把事实写成文字，和用量账本一样。
3. 回放沿用用量账本的做法：接口带 `?until=<seq>`，服务端按事件前缀算出那一刻的状态。
4. 待处理决定先落库：现在它们只在服务端内存里（`Pending`），重启后要从事件重建；迁移收件箱之前，先让服务端在 SQLite 里记着哪些请求还在等谁，收件箱只读这一份。
5. 应用里只留界面自己的状态：折叠、草稿、推迟和忽略（这个人自己的视图）、会话按轮分组的显示（`ChatTurns`）。
6. 迁移期间不新增应用侧的推导：新的事件和状态先在服务端算，再由应用读。

## 迁移顺序

1. 待处理决定落库，服务端给出 `GET /api/inbox`（全部 Run 等用户处理的事）和全局事件流上的 `inbox` 通知；应用的收件箱改读它，删除 `Inbox.entries` 和 `InboxModel` 对每个 Run 的事件推导。
2. 看板事实：`GET /api/runs/{id}/board?until=`，替换 `boardFacts`（等谁处理、结果、交接、负责人的决定）；冲突是否被覆盖这类规则只在服务端写一次。
3. Run 状态：`GET /api/runs/{id}/state?until=`，替换 `derive` 的任务、Agent 阶段和负责人轮次；`AgentPhase` 中现在只有应用会推出的协调中、等其他 Agent 和出错由服务端写出。
4. 交付的审阅阶段和信号写进服务端的结果，删除 `reviewStage` 和 `reviewSignals`。

每一步都把对应的 Swift 测试（`DeriveTests`、`ReviewTests` 等）换成服务端的测试，端到端场景逐项比较应用状态和服务端结果。

## 取舍

- **结构化事实而不是界面文字**：服务端给文字就要按界面语言出两版，还会让应用无法调整措辞；给事实则界面文案仍归应用，服务端的测试只核对事实。
- **按步迁移**：四块推导互相依赖（收件箱用看板事实，看板事实用 Run 状态），一次换掉风险太大；每一步完成时两边不再各算一份那一块，迁移中间的版本仍然只有一份事实来源。

## 后果

- 新增或修改事件时不再同步 `Derive.swift`；迁移完成前，已有的推导按原样维护，只修错误。
- 应用测试里的推导用例随迁移移到服务端。
- 迁移完成后删除 `Derive.swift` 的 `derive` 和 `boardFacts`、`Inbox.swift` 的推导和 `Review.swift` 的阶段计算，[macOS 应用](../architecture/20261031-frontend.md#event_derivation)的「由事件推导状态」一节改写为「读服务端的状态」。
