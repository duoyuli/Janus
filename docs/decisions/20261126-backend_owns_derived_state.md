# ADR：由事件推导的状态只在服务端算

- 状态：已采纳（accepted），记录于 2026-11-26，用户在 2026-11-25 定下方向，2026-11-26 补充了 Web 版本的目标和下面第 2、5 条。取代 [ADR：用原生 macOS 应用做展示层](20261101-native_macos_app.md) 的第 4 条（事件推导 `derive` / `boardFacts` 在 Swift 中实现）。还没迁完的部分见下文「迁移顺序」和 `LESSONS.md` 的未解决项。
- 相关文档：[由事件推导状态](../architecture/20261031-frontend.md#event_derivation)、[收件箱](../architecture/20261031-frontend.md#inbox)、[交付的审阅](../architecture/20261031-frontend.md#review)、[HTTP API：Run 的视图](../interfaces/20261031-http_api.md#run_view)、[ADR：事件是唯一事实来源](20261031-events_as_source_of_truth.md)。

## 背景

应用从事件日志自己推导 Run、任务和 Agent 的状态、看板上的待办、收件箱条目和交付的审阅阶段（原来的 `Derive.swift` 的 `derive` 和 `boardFacts`、`Inbox.swift`、`Review.swift`），服务端为调度、看板和恢复也推导一份。两份在同一批事件上各算各的：2026-11-25 负责人交出的提问在交付后没被撤回，服务重启后待处理决定只剩应用推导出的卡片，点哪个选项都被服务端拒绝。用户要求事件和由事件推导的状态都在服务端 Rust 中计算，应用只展示。

2026-11-26 用户补充：以后要做一个功能和 macOS 客户端对齐的 Web 版本，「要让 UI 做纯展示，以后所有的计算都要放到 Rust 里面去」。两个客户端各算一份，每条规则和文案都要写两遍，迟早说法不一（`LESSONS.md` 的 L-35）。

用量账本早就这样做了：只在服务端算（`usage.rs`），应用读 `GET /api/runs/{id}/usage?until=`。

## 决策

1. 由事件推导的业务状态只在服务端算一份（`backend/src/run_view.rs`）：Run、任务和 Agent 的状态，等人处理的请求，看板上挡着工作的事、结果、交接和决定，交付的审阅阶段、要看的信号和这一轮的要求，每个会话显示哪些事件、轮到谁、输入框提供什么，收件箱条目。客户端读 `GET /api/runs/{id}/view` 和 `GET /api/inbox`，不从事件推导这些状态。
2. 服务端按客户端要的语言（`lang`，中文或英文）写好这些条目的文字（标题、说明、下面一行、徽标），同时给出结构化的字段（种类、关联的子任务和成员、数字），供按钮、跳转和测试使用。快捷回答直接给出要发的请求体。2026-11-26 用户选了这一种，取代最初的「服务端只给事实，应用写文字」：有了 Web 客户端，文字放在客户端就要写两份。界面本身的文字（按钮、标题栏、空状态）仍在客户端。
3. 回放沿用用量账本的做法：接口带 `?until=<seq>`，服务端按事件前缀算出那一刻的状态。
4. 待处理的请求从事件推出，不另存一张表：服务端撤回一个请求时一定写 `decision.withdrawn`（会话结束、服务重启时），所以事件和服务端内存里等着回答的请求一致；另存一份会违反合并前检查第 10 条（能由已有状态推出的值不另存）。最初的第 4 条（待处理决定先落库）因此不做。
5. 收件箱的推迟和忽略存在服务端（`inbox_marks` 表）：同一个人在 Mac 和 Web 上看到同一个收件箱。2026-11-26 用户选了这一种，取代最初的「推迟和忽略是这个人在这台电脑上的视图」。客户端只留界面自己的状态：用户点开或收起了哪些行、草稿、选中的页签、外观、显示档位。会话按轮分组原来也算作界面的显示留在客户端，2026-11-26 同样移到服务端（「以后所有的计算都要放到 Rust 里面去」）：服务端按显示档位排好行，客户端只在这些行上应用用户自己的点按，不重新分组。
6. 不再新增客户端侧的推导：新的事件和状态先在服务端算，再由客户端读。

## 实现

- `run_view::Fold` 是一个逐事件的折叠：`RunState::apply` 推出状态，`BoardFold::apply` 记下看板需要的其余东西，`sessions::SessionFold` 记下每个会话的事件和每个 Agent 自己的轮次。服务端为被问到的 Run 各留一个折叠，记着推到哪一条事件（`run_view::Views`），下次只折叠新事件；收件箱不再跟踪的 Run 被放掉，删除 Run 时一并忘掉。
- `Fold::view` 在折叠之上算出看板、审阅和会话，由 `words::Words` 按语言写文字；`inbox::inbox_entries` 用同一个视图写出收件箱条目。会话的行（`turns`）、旁边的计划、控制项、命令、用量和 Git 信息（`aside`）都在视图里；折叠时还记下会话显示的事件、事件带的改动行（`diffs`）和文档候选（`docs`）。输入框的建议是单独的接口（`suggest`），实时预览由每条事件流自己算（`preview`）。
- 客户端显示的文件（文档和它链到的图片、diff、贴进来的图片、运行组件日志）都经 HTTP 读（`http/files.rs`），只给这个 Run 点名的或 Janus 为它存的文件，见[安全边界](../operations/20261031-security.md#run_files)。
- 应用的 `RunModel.loadServed` 在读入 Run、每批新事件之后、回放位置改变和换语言时读视图，`InboxModel.refresh` 在全局事件流有新事件或 `inbox` 通知、以及下一条推迟的回来时读收件箱。

## 迁移顺序

已完成（2026-11-26）：收件箱和推迟、忽略；看板事实；Run、任务、Agent 和会话的状态及输入框模式；交付的审阅阶段、信号和这一轮的要求。之后同一天完成：会话按轮分组和哪些事件显示（含冲突被越界覆盖时的隐藏，原第 2 项的 `ChatItem.visible`）；会话里的计划、控制项、斜杠命令、上下文用量、待发送的消息和输入框的建议，任务的 Git 信息和尝试的说明（原第 3 项）；文档清单、diff 的解析和审阅消息、实时预览，以及应用从 Janus home 读的文档、diff、图片和运行组件日志改经 HTTP（原第 4 项）。还有（原第 1、2、5 项）：每个 Run 现在能做哪些操作（暂停、继续、停止、立即开始、验收、从中断处继续、删除，`run_ops::allowed` 同时用于执行和视图的 `actions`，应用和服务端在已交付、已验收的 Run 能否继续上从此一致），只读和中断续跑的提示；验收证据的分组、计数、提醒和强度，交付每个子任务的一行和这一轮的数字行；进展时间线；运行卡片的状态胶囊和团队面板每个成员的一行；审计页的五条系统规则；值班的排序；列表里 Run 的标题和状态胶囊（对话的标题、排队的位置）；数字员工不能用的原因、工作区跑不起来的原因和新工作区的默认团队；资源库 Skill 的目录顺序和按来源分组；工作区页「等你处理」按 Run 的归组。再之后（Web 第二批）：Run 属于哪个工作区（列表每行的 `workspace`，原 `AppStore.belongs`）、侧栏里哪些工作区在干活、已删除的工作区、第一个任务前的步骤、数字员工的分组顺序、工作区的团队一行和共享资料字数、「等你处理」每行的颜色。

还没迁的应用侧计算（2026-11-26 清点），按 Web 客户端需要的程度：

1. 会话里每条事件怎样写成一行：工具调用的动词和对象（`ToolRow.label`）、看板工具的说明、尝试标题里的任务和模型、子任务页执行轨迹挑出的事件。
2. 头像图片裁成正方形（`AvatarImages.square`，上传前在应用里做），Agent 编辑器里隔离目录的路径提示（`JanusHome.agent`）。
3. 剩下的小项：复制交付摘要的文字拼接（`RunModel.copySummary`），交付收成一行时按阶段写的那句话（`ReviewLine`）。

只能在 Mac 上做的不迁：启动服务、应用更新、macOS 权限、系统通知。

## 取舍

- **服务端写文字**：服务端要为每条带两种语言的文字，测试要核对文字；换来的是 Mac 和 Web 永远说同一句话，规则和文字只改一处。
- **增量折叠而不是存派生表**：派生状态不落库，服务重启后第一次被问到时从事件重算一次；省掉迁移和两份数据的一致性问题，代价是重启后第一次读稍慢。
- **按步迁移**：一次只换掉一块，每一块换完时两边不再各算一份。

## 后果

- 新增或修改事件时，只改 `run_view`（和服务端自己的调度）；Swift 里没有 `derive`、`boardFacts`、`reviewStage`、`reviewSignals`、`roundRequests`、会话的轮次规则，也没有按轮分组（`ChatTurns`）、会话旁边的读取（`SessionView`）、实时预览的合并（`ChatLive`）、文档清单（`RunDocs`）和 diff 的解析（`Diff`）。
- 这些推导的测试在 `backend/src/run_view/tests`；端到端场景逐项比较应用状态和服务端结果。
- 以前记在应用本机设置里的推迟和忽略不搬到服务端（数据版本 31），升级后推迟过的条目回到「待处理」。
