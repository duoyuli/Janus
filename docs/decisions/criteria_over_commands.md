# ADR：按验收标准自行验证

- 状态：已采纳（accepted），记录于 2026-10-31。取代主控为任务指定验证命令、由 Janus 在允许列表内执行的做法。
- 相关文档：[看板 MCP 工具](../interfaces/board_mcp.md#acceptance_criteria)、[Run 生命周期](../domains/run_lifecycle.md#verification)、[目标模式与共享看板](../domains/goal_mode.md#failures_in_goal_mode)。

## 背景

早期的编排中，主控给每个任务写验证命令（`commands`），Janus 在任务完成后按一份只读命令和测试命令的允许列表执行，退出码非 0 即失败。一次真实 Run 暴露了这套做法的问题：主控给调研任务写了 `git status`，而工作目录不是 Git 仓库，协作者两次都给出了正确结论，也在风险中预见到这条命令会失败，任务却两次被判失败，下游任务被阻塞。为此加过的补救（拒绝 shell 语法、非 Git 目录不允许 git、预先检查程序是否存在）都在给同一个僵硬的机制打补丁。用户指出：不应该把 Agent 限制在某几条命令上，应该给验证的标准，充分利用 Agent 自己的推理能力完成验证。

## 决策

1. 每个任务必须有验收标准（`accept`），写结果和行为，不写成具体命令。
2. 执行者用自己判断合适的方式逐条验证（运行测试、启动程序、读代码推理、对比输出），在结构化结果的 `checks` 中逐条给出是否达到和证据。
3. Janus 不运行任何验证命令，只核对结构：每条标准都有 check、有证据、没有自认未达到的。删除 `commands`、命令允许列表和相关检查。
4. 没通过核对时，先在原会话里补一次；仍不行交给主控，由主控核对后接受、重试（可改标准）或取消。
5. 独立核对由主控负责：执行者的证据是它的说法，主控自己核对关键结果，改了代码的目标安排独立评审。

## 取舍

- **与 Janus 执行命令相比**：验证方式不再受允许列表限制，Agent 可以启动程序、看实际表现、写临时脚本，适用于任何技术栈；不会再出现「结果正确、命令不适用」的误判。代价是 Janus 失去了一道由自己执行的客观检查，正确性更依赖执行者的诚实和主控的核对。
- **安全**：不再需要为了安全限制验证命令。执行者运行什么命令由它自己的权限模式决定，与[权限交给 Agent 原生模式](agent_native_permissions.md)一致。

## 后果

- 编排缺少验收标准时被退回。
- 旧 Run 的 `orchestration.accepted` 中的 `verification.commands` 在恢复时被忽略；`verification.command*` 事件只出现在旧 Run 中。
- 角色的执行统计中，「验证没通过」指没通过验收核对。
