# ADR：集中引导 macOS 权限，升级后重新检查

- 状态：accepted
- 日期：2026-11-17
- 范围：macOS 应用的完整磁盘访问、应用程序管理和屏幕录制；不改变 [Agent 原生权限模式](20261031-agent_native_permissions.md)。

## 背景

目前发布包使用 ad-hoc 签名。2026.11.17.3 和 2026.11.17.4 的指定要求分别绑定不同的代码哈希，新版本不满足旧版本的身份要求，已有 macOS 权限可能不能沿用。用户要求暂不配置证书，在设置中集中申请权限，并在升级后提示重新授权。

## 决策

- 设置增加「macOS 权限」，集中展示完整磁盘访问、应用程序管理和屏幕录制的用途、状态及授权入口。「一键开始授权」按顺序引导，每次只处理一项，允许跳过或稍后处理。
- 屏幕录制使用 `CGPreflightScreenCaptureAccess` 查询、`CGRequestScreenCaptureAccess` 申请；检查时不截图。完整磁盘访问和应用程序管理只引导到系统设置，不读取 TCC 数据库、不探测私人文件、不修改其他应用来试探权限。没有可靠公开查询接口的状态明确写为「需手动确认」，用户确认后显示「已手动确认」，不等同于系统检测到授权。
- 安装包首次启动和版本、构建、代码签名哈希或安装路径变化后的首次启动，检查可查询的权限并弹出集中引导。普通启动也刷新屏幕录制状态，但同一安装版本关闭过的引导不反复弹出。回到应用时刷新可查询的状态。
- 仅在 Janus.app 内发起系统权限申请。源码运行和单元测试不向宿主终端申请权限。检查和引导状态由应用模型持有，通过注入的系统接口测试，不使用进程级可变单例。
- `~/.janus/permissions/review.json` 只保存安装标识、是否展示过引导以及用户手动确认过的项目，不保存系统权限结论。新的安装标识使旧确认失效。此文件不包含凭据，也不能授予权限。
- 权限归属由 macOS 决定。本页检查的是 Janus 自己；经独立服务、其他终端或不同负责进程启动的 Agent 不保证沿用 Janus 的授权。界面说明这种边界，用户按系统提示选择实际执行程序。

## 取舍

完整磁盘访问和应用程序管理无法实现可靠的静默检测和程序自动授予。集中引导减少寻找设置入口的步骤，系统授权仍由用户确认；手动确认只表示用户已检查设置。完整磁盘访问不绕过 UNIX 权限、SIP 或其他系统保护，也不改变 Agent 的沙箱模式。

没有固定签名身份时，升级后的重新授权仍可能发生。这个决定补充 [应用内增量更新](20261102-in_app_updates.md)，不替代其中的固定签名方案，也不扩大更新来源。

## 后果

应用新增三个权限入口和升级后的引导，未授权不阻止应用启动或普通任务。2026-11-18 起发布改用固定的自签名证书签名（[ADR：应用内增量更新](20261102-in_app_updates.md)），bundle id 改为 `io.github.duoyuli.janus`，权限在之后的更新中保留；安装标识随之改为 bundle id 和签名身份，同一签名的更新不再弹出引导；屏幕录制卡片补充了「已打开却检测不到」的处理办法和「重新打开 Janus」。测试覆盖首次启动、同版重启、新构建确认失效、拒绝或跳过、系统设置打开失败、手动确认与系统检测的区别，不操作测试机器的真实权限。
