# ADR：Janus 写给 Agent 的文字跟随应用语言

- 状态：已采纳（accepted），记录于 2026-11-25。取代「Janus 编写的系统层说明始终用英文」的做法（原写在 [ACP 集成](../interfaces/20261031-acp_integration.md#standing_instructions)）。
- 相关文档：[注入的语言](../domains/20261031-goal_mode.md#prompt_language)、[HTTP API](../interfaces/20261031-http_api.md)、[数据模型](../architecture/20261031-data_model.md#migrations)、[ADR：Janus 只注入协作规则](20261125-collaboration_only_injection.md)。

## 背景

Janus 写给 Agent 的文字原来两种语言混用：系统层（负责人说明、协作者约定、值班、团队记忆）是英文，第一条提示、看板消息、工具说明和返回是中文。同一个会话里，同一条规则可能一处英文、一处中文。用户要求：注入的文字按应用的语言来，应用是中文就注入中文，应用是英文就注入英文。服务端原来不知道应用的语言，语言只存在应用本地。

## 决策

1. 每一段注入的文字都有中文和英文两版：系统层、提示、插话、看板消息、MCP 工具的说明和返回、生成的 `janus-skills`。只给应用和用户看的文字（事件标题、接口错误、日志）不在其中。
2. 应用把界面实际用的语言（「跟随系统」换算成中文或英文）用 `PUT /api/language` 告诉服务端：每次连上全局事件流时，以及在设置里换语言时。服务端存为一项设置，没有时是中文。
3. Run 创建时把当时的语言写进快照（`config.lang`），之后不变；换语言只影响之后创建的任务、对话、值班和整理。
4. 读回 Agent 写的标题（结论、需要你决定、建议更新共享资料）时两种语言都认。
5. 数字员工指令、Provider 自定义提示词、共享资料、用户消息和历史对话保留原文，不翻译。

## 取舍

- **固定在 Run 上，而不是每次读当前设置**：一个任务的会话不会半路换语言，系统层和之后的提示一致；代价是长期存在的对话和值班不随换语言改变，要新建才换。
- **应用推送，而不是服务端读系统语言**：服务端是后台进程，系统语言不等于用户在 Janus 里选的语言；应用连上时推送，服务端重启后第一次连上就补上。
- **两版都手写，而不是运行时翻译**：没有翻译依赖，也不会把工具名、JSON 键译错；代价是改一段文字要改两处，测试为两种语言各留断言。

## 后果

- 新增 `backend/src/lang.rs`（`Lang`、`tr!`、语言设置的读写），`configs` 多一类 `language`，数据版本 24 给以前的 Run 记为中文。
- 交付标题的常量改为一对中英文（`Heading`）。
- 端到端测试的应用默认用简体中文，`language` 场景用英文核对服务端记下的语言和注入的文字。
