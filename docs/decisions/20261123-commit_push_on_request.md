# ADR：用户要求时 Agent 提交、推送和部署

- 状态：已采纳（accepted），记录于 2026-11-23。
- 修订：[ADR：验收时把结果合并回任务开始时的分支](20261120-merge_back_on_accept.md) 的第 2 条「每次验收在源分支上是一个提交」：Run 自己的提交也一起带回。
- 修订：第 4 条「从 worktree 推送」被 [ADR：交付时把结果合并回分支](20261123-merge_back_on_delivery.md) 修订：推送前先在 worktree 里变基到最新的分支，交付时用户的分支快进到同一个提交；Agent 的提交随交付带回。
- 相关文档：[谁来做决定](../domains/20261031-goal_mode.md#decision_ownership)、[协作者的约定](../domains/20261031-goal_mode.md#collaborator_rules)、[Run 生命周期](../domains/20261031-run_lifecycle.md#workspace_model)、[安全边界](../operations/20261031-security.md#workspace_access)。

## 背景

负责人说明里有一句无条件的「Do not commit, push, or deploy.」，协作者的约定和 worktree 说明里也有同样的禁令。用户在目标里写了「提交并发布」，Codex 负责人仍然回复「当前工作区规则禁止我直接 commit、push 或 deploy」，跑完验证就停下，改动留在未提交状态。

这条禁令只是提示词，不是权限拦截：Agent 按自己的权限模式本来就能运行 `git commit` 和 `git push`，见 [ADR：权限完全由 Agent 原生模式决定](20261031-agent_native_permissions.md)。它的效果只是让 Agent 把 Janus 的固定约定放在用户明确的要求之上。

## 决策

1. **用户要求才做，只做到要求的程度**：负责人说明写成「只有用户在目标或回答里要求时，才提交、推送、部署或发布，并且只做到用户要求的程度：要求提交不等于要求推送」。用户的要求就是用户的决定，负责人照做，不再用 `ask_user` 重复确认；没有要求时三件事都不做。子任务要做其中一件时，负责人在子任务说明里写明。
2. **协作者听子任务说明**：协作者的约定改为「只在子任务说明要求时提交、推送或部署，并且只做到说明要求的程度」。协作者看不到用户的目标，授权经负责人的说明传下去。「不改工作目录之外的文件」不变。
3. **worktree 里的提交随验收带回**：没有要求提交时，改动保持未提交，验收时由 Janus 提交。Run 自己的提交在验收时连同 Janus 为剩下的改动做的那一个提交一起带回源分支；源分支在这期间有了新提交时，它们会被变基重放，提交号随之改变（`worktrees::accept` 本来就重放任务开始或上次验收之后的全部提交，代码不用改）。
4. **从 worktree 推送**：worktree 处于 detached HEAD，不在任何分支上。负责人说明写明推送的方法（`git push origin HEAD:<分支>`，源分支已知时写出分支名），任务提示告诉协作者把 HEAD 推到说明指定的分支。
5. **Janus 自己仍不推送、不部署**：Janus 的 Git 写操作范围不变，见[安全边界](../operations/20261031-security.md#workspace_access)。

## 取舍

- **跟随用户的要求，而不是加开关**：是否提交、推送由用户在目标里说清楚，不在工作区或数字员工上加一个设置项；权限仍由 Agent 的原生模式决定，Janus 不另加校验。
- **用户的要求即授权，不再询问**：推送和部署是影响工作目录之外的不可逆操作，没有要求时仍归用户决定（`ask_user`）；用户已经在目标里要求了，再问一遍只会让 Run 停下等人。
- **推送早于验收时的风险**：Agent 推送后，源分支如果又有了新提交，验收会把 Run 的提交变基到新分支上，本地分支和已推送的远端分支会分叉。这由 Agent 按用户的要求和仓库的状况处理，Janus 不在验收时替用户解决。

## 后果

- 负责人说明的「谁来做决定」中，不可逆或影响工作目录之外的操作只在用户没有要求时才用 `ask_user`。
- 验收带回的不一定只有一个提交：Run 在用户要求下自己做的提交也在源分支的历史里，排在 Janus 的提交之前。
- 安全文档的「工作目录访问」一节改为：Agent 只在用户要求时提交、推送或部署，这仍只是指令，不是强制。
