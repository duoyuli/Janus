# ADR：任务页是一个群

- 状态：已采纳（accepted），记录于 2026-11-27。只改 Mac 应用；Web 客户端暂时保留原来的版式。
- 相关文档：[macOS 应用：群聊式的工作台](../architecture/20261031-frontend.md#run_group)、[HTTP API：Run 的视图](../interfaces/20261031-http_api.md#run_view)、[共享看板](../domains/20261031-goal_mode.md#board_flow)、[ADR：由事件推导的状态只在服务端算](20261126-backend_owns_derived_state.md)、[ADR：负责人派出子任务后只做管理](20261119-lead_manages_after_delegating.md)。

## 背景

负责人派完活以后，任务页（工作台）从上到下堆着运行卡片、待处理、交付、折叠的进展时间线、负责人的对话和旁边四个页签的检查器，子任务的会话在另一页。每一块都对，但合起来不像一个团队在干活：谁在做什么要在检查器和时间线之间来回找，组员和负责人之间说了什么只能进子任务页或审计日志看，等你处理的事和它的来龙去脉分在两处。

换成人的视角，一个团队协作最熟悉的样子是项目群：需求方在群里提需求，项目经理分工，组员在各自的话题里来回，要大家知道的事发到群里，要谁处理就 @ 谁。负责人和协作者经看板协作本来就是这种结构（派工、进展、提问、交结果、验证、返工、交付），缺的是按这个结构画出来。

还有一点：负责人是自主推进的。它可能分几批派活、中途追加任务、自己回答组员、返工、交付后接着改。任何按「规划 → 执行 → 验证 → 交付」固定阶段画的页面都会在这些地方变形。

## 决策

1. 任务页是一个群：成员是这次的团队，群里的时间线就是负责人的会话，团队的群消息按事件顺序插在里面。没有阶段：标题的状态、成员此刻在做什么、等你处理的件数、子任务进度都从「到这一刻为止发生了什么」推出来。
2. 群里只放大家都该知道的事和要人的事：派工、开工和交接、交结果和验证判定、返工和取消、冲突、可能卡住和阻塞、你发给组员的话、转给你的提问、审批和表单、交付。组员和负责人之间的来回（进展、备注、提问、回答、负责人的指示）只在那个子任务的话题里，群里不刷屏。
3. 每个子任务是一个话题：负责人派的活、和它有关的全部消息，旁边是它的工作记录（协作者的会话）。别人的屏幕不在群里刷：群底部只留一行「研发工程师 在跑 pytest -q · T2」。
4. 等你处理的就是 @你：消息黄底，卡片就地处理，标题旁的「@你 N 件」一次跳一件；处理完卡片收成一行结论。
5. 派工卡片原位更新状态，不另发「T1 开始了」之类的消息；开工和交接只是一行灰字。
6. 群消息、话题、正在干活的人和 @你 都由服务端写好（`backend/src/run_view/feed.rs`，视图的 `feed` 和负责人会话里的 `post` 行），应用只画。客户端读视图时带 `group=1` 才把群消息插进负责人的会话，不带时负责人的会话和原来一样。

## 取舍

- **负责人的会话就是群，不另建一条消息流**：负责人说的话、它折叠起来的工具调用本来就在它的会话里，按轮分组、折叠、实时预览、滚动跟随都已经做好（[会话卡片](../architecture/20261031-frontend.md#session_view)）。把群消息作为一种行插进去，比另建一条要和会话对齐时间的消息流简单，也不会出现两边顺序对不上。代价是看板推进负责人这一轮的消息和群消息重复，群里不再单列它们。
- **话题而不是全部进群**：协作者的进展和它与负责人的来回量大，全进群就回到一块大看板。人的项目群也是这样分的：要大家知道的发群里，细节在话题里。哪些消息进群定在服务端一处（`Post::group`），以后要调只改一处。
- **用 `group=1` 而不是直接改负责人的会话**：Web 客户端这次不动，它不认识 `post` 行，看板推送也还要单列。等 Web 跟上，两边都按群排时可以去掉这个参数。
- **左对齐**：Agent 的回复常有长文、代码和表格，卡片也宽；左对齐（像 Slack 和飞书话题群）比左右气泡好排。
- **进展时间线从 Mac 去掉**：群本身就是时间线，派工卡片和开工、交接的灰字说清楚了谁在什么时候做了什么、交给了谁。服务端的 `timeline` 保留给 Web。

## 后果

- Mac 的工作台换成 `GroupView`（`UI/Run/Group.swift`、`Posts.swift`、`GroupSide.swift`），运行卡片、待处理一节、进展时间线和检查器删除；它们的内容分别到了群标题、群里的 @你、群消息和右栏。子任务页和审计、团队页保留。
- 视图多了 `feed`（`topics`、`typing`、`mentions`）和 `group` 参数；负责人会话的 `rows` 在 `group=1` 时多一种 `post` 行。
- Web 的 Run 页暂时和 Mac 不同：仍是运行卡片、待处理、交付、进展时间线、负责人对话和检查器，见 [Web 客户端：Run 页](../architecture/20261126-web.md#run_page)。
