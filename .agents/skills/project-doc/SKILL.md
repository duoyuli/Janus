# Project Doc

文档库记录需要跨多个代码位置才能理解的持久工程知识，由索引逐层路由：根 `index.md` 指向分类 `index.md`，分类索引列出该分类的全部文档。代码中的 `@project-doc <路径>#<章节 ID>` 注释（锚点）指向解释那段代码的章节。本 skill 规定怎样阅读文档库，以及怎样让索引、正文、锚点与当前实现保持一致。

## 每个任务

1. 判断任务是只读还是已授权修改文件。只读任务只报告文档与代码的不一致，不修复。
2. 确定文档根目录：项目指令声明的路径；没有声明时用意图明确的既有文档目录，否则用 `docs/`。
3. 分析业务代码前先读根 `index.md`，按其中的「阅读时机」进入匹配的分类索引，再读任务需要的章节。
4. 遇到锚点时，在解释、审查或修改那段代码前读目标章节，以及理解它所需的范围说明、术语和直接依赖的章节。路径或章节 ID 无效的锚点按文档与代码不一致处理。
5. 存在 `<doc_root>/.project_doc_bootstrap.md` 时，读完根索引后读它，从其中记录的下一步继续，保留已完成的工作。

项目指令声明了 Project Doc gate，但根索引和初始化备忘录都不存在时，停止任务并报告配置不完整。常规任务不创建文档库，用户明确要求时才创建。

## 阅读与上下文复用

每份材料（本 skill、参考协议、索引、文档章节）在一个会话中读一次，之后的任务、子任务、文件编辑和交付都复用，不重读。

- **首次阅读**：在仓库的第一个任务中完整阅读根 `index.md`。分类索引和正文按需阅读；任务扩展到未读区域时，按已知路由补读，已读的部分继续复用。
- **复用的条件**：上下文或压缩摘要中仍保留要用到的内容，即路由的分类、路径、阅读时机和当前操作的约束。只记得读过，或只剩文件名，都算内容缺失，重读缺失的索引或章节；根索引的路由信息丢失时重读整个根索引。
- **刷新**：已知文件在会话外被修改、仓库或文档根目录变更、路由与实际文件冲突，或用户要求刷新时，重读受影响的内容。本会话中自己做的修改只要还在上下文中就直接使用。按这些已知事件判断，不在每次操作前检查时间戳或哈希。
- **边界**：复用只减少重复阅读，文档影响评估和验证照常进行。复用状态只留在会话上下文中，不写缓存文件、已读清单或「无影响」声明。

## 随代码维护文档

已授权修改文件的任务，在同一次变更中维护代码、文档正文、各级索引、锚点和普通链接。

1. 根据任务涉及的代码路径、符号、配置、测试和锚点，找出可能受影响的章节并阅读。
2. 出现以下变更时更新文档：
   - 对外或跨模块的行为、接口、事件、错误处理。
   - 领域规则、状态转移、不变量、权限、安全限制。
   - 配置、数据模型、迁移、部署、恢复、可观测性流程。
   - 代码或文档移动导致路径、符号位置、普通链接或锚点变化。
   - 发现文档与已验证的当前行为不一致。
3. 不改变已记录行为的内部重构不改正文，只修复受影响的引用和锚点。
4. 新知识优先扩展主题、受众和更新周期相同的现有章节；确需新建文档时命名为 `YYYYMMDD-<主题>.md`（创建日期加小写 `snake_case` 主题），并在所属分类索引中登记。单个函数就能看懂的事实、机械重构、测试 fixture、生成代码、临时方案和工作进度留在代码、提交历史或方案文件中。
5. 现状文档只描述当前状态。重要的历史决策写成 ADR，被取代的 ADR 保留并标记为 `superseded`。`research/` 的调研报告和 `review/` 的审查报告是时点快照，写成后不随代码更新；它们的结论落到现状文档、ADR 或代码中。
6. 锚点的目标是标题前的 `<a id="..."></a>`，不是由标题生成的 slug。修改标题用词时保留 ID；章节被移动、拆分或删除时，同步处理指向它的每个锚点。
7. 文档与代码不一致时，任何一方都可能是错的。先用用户需求、测试、schema、调用方、ADR 和变更历史核实设计意图，再在授权范围内修正错的一方；关键歧义无法解决时问用户。
8. 在仓库根目录运行 `python3 <skill_dir>/scripts/check_library.py --changed`（文档根目录不是 `docs/` 时加 `--doc-root <路径>`），机械检查受影响的索引链接、成员命名、章节 ID 和锚点。脚本判断不了的内容用针对性阅读和 Git diff 核对：事实是否正确，锚点是否在实现该规则的代码旁。代码变更需要的测试照常运行。
9. 在回复中说明改了哪些文档；没有受影响的文档时，说明已评估文档影响。

`check_library.py` 是 skill 自带的只读脚本，直接运行，不复制进仓库。项目自己的验证脚本、CI 检查和文档影响声明，只在用户明确要求时创建。

## 参考协议

上面的规则足够完成日常的阅读和随代码维护。只在下列情况读对应的参考文件：

| 情况 | 阅读 |
| --- | --- |
| 新建、移动、合并或删除文档与分类，修改索引条目，编写 ADR、调研或审查报告 | [references/library_protocol.md](references/library_protocol.md) |
| 新增、移动或删除锚点，修改被锚点引用的章节 ID，修复损坏的锚点 | [references/anchor_protocol.md](references/anchor_protocol.md) |
| 用户要求创建、恢复或重建文档库，安装或修复 Project Doc gate | [references/bootstrap_workflow.md](references/bootstrap_workflow.md) 和上面两份协议，模板在 `assets/` |
| 一致性审计 | 上面两份协议 |

一致性审计先运行不带 `--changed` 的 `check_library.py` 得到结构问题清单，再人工核对正文事实、锚点位置和入口点覆盖，并检查各智能体指令入口的 gate 是否缺失或过期。已授权时修复，否则只报告。
